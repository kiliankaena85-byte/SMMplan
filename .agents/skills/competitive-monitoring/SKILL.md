# Competitive Monitoring — живая система мониторинга

## When to activate

- Пользователь просит отслеживать изменения на сайте конкурента
- Запущен процесс регулярного конкурентного аудита
- Клиент просит «сделайте как у X» — нужен быстрый анализ
- Проектируется новый раздел и нужен актуальный конкурентный контекст
- Настроены триггеры для автоматического мониторинга

## ТРИГГЕРЫ ДЛЯ АВТОМАТИЧЕСКОГО АНАЛИЗА

### Триггер 1: Изменение на сайте конкурента
Browser Agent → screenshot diff → анализ изменений
Вопросы агента себе:
- Что изменилось? (CTA / pricing / hero / copy)
- Почему они это изменили? (A/B test / rebrand / new segment)
- Нужно ли нам реагировать? (да / нет / в backlog)

### Триггер 2: Запрос клиента «сделайте как у X»
Агент НЕ копирует немедленно. Агент запускает протокол:
1. Screenshot + decode за 2 минуты
2. 3 уточняющих вопроса клиенту
3. Feasibility check за 1 минуту
4. Предложение: steal / adapt / reject с обоснованием

### Триггер 3: Проектирование нового раздела
Агент автоматически:
1. Ищет 3 примера из конкурентов / индустрии
2. Создаёт аннотированные карточки
3. Предлагает клиенту сравнение
4. Спрашивает о предпочтениях и ограничениях

## Step-by-step execution protocol

1. **Setup monitoring**: Определить список конкурентов и частоту мониторинга
2. **Screenshot baseline**: Сделать начальные скриншоты всех ключевых страниц
3. **Store in brain/**: Сохранить baseline в `.gemini/antigravity/brain/competitors/`
4. **Schedule checks**: Настроить регулярные проверки (еженедельно / при запросе)
5. **Diff detection**: Сравнить текущие скриншоты с baseline
6. **Analyze changes**: Для каждого изменения — провести decode анализ
7. **Generate report**: Сформировать отчёт с рекомендациями
8. **Update brain/**: Обновить baseline и историю изменений

## Scope boundaries

### DOES
- Отслеживать визуальные изменения на сайтах конкурентов
- Анализировать смысл и причину изменений
- Формировать рекомендации по реакции
- Хранить историю изменений в brain/
- Быстро реагировать на запросы «сделайте как у X»

### DOES NOT
- Отслеживать изменения backend / API конкурентов
- Заменять A/B тестирование
- Гарантировать правильность интерпретации изменений
- Мониторить SEO-позиции (используйте специализированные инструменты)

## Error handling

| Scenario | Response |
|----------|----------|
| Сайт конкурента недоступен при проверке | Повторить через 1 час, если повторно — уведомить пользователя |
| Изменение косметическое (новый favicon) | Классифицировать как «low priority», не уведомлять |
| Обнаружен A/B тест у конкурента | Зафиксировать обе версии, отметить как «эксперимент» |
| Слишком много изменений одновременно | Приоритизировать по влиянию на конверсию |
