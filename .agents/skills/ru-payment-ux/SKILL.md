# Платёжный UX рынка РФ — чекаут, рассрочки, фискализация

## When to activate

- Проектирование чекаута для российского рынка
- Настройка платёжных методов (СБП, SberPay, рассрочки)
- Фискализация по 54-ФЗ
- B2B оплата с ИНН
- Пользователь упоминает: оплата, чекаут, СБП, рассрочка, SberPay, кассовый чек, ИНН

## ЧАСТЬ 1: ПЛАТЁЖНЫЙ ЛАНДШАФТ РФ 2025-2026

### 1.1 Распределение способов оплаты

| Метод | Доля в e-commerce | Тренд |
|-------|-------------------|-------|
| Банковская карта | 55-60% | Стабильно |
| СБП (QR) | 15-20% | Рост +30% год к году |
| Электронные кошельки | 10-12% | Стабильно |
| Наличные при получении | 10-15% | Снижение |
| Рассрочка/кредит | 8-12% | Рост +25% год к году |
| Криптовалюта | <1% | Ниша |

### 1.2 Ключевые отличия от западного рынка

- **Рассрочки — норма:** 50%+ покупок электроники и бытовой техники в рассрочку
- **Наличные при получении:** значимая доля, особенно в регионах
- **QR-оплата (СБП):** уникальный для РФ метод, растущий
- **Фискализация:** каждый платёж должен генерировать чек по 54-ФЗ
- **ИНН для B2B:** обязательное поле при корпоративной оплате

## ЧАСТЬ 2: ПЛАТЁЖНЫЕ МЕТОДЫ — ДЕТАЛЬНЫЙ РАЗБОР

### 2.2 СБП (Система Быстрых Платежей)

QR-оплата через приложение банка. Без комиссии для покупателя.

**UX паттерн:**
1. Пользователь выбирает «Оплата по QR-коду (СБП)»
2. Отображается QR-код
3. Пользователь сканирует в приложении банка
4. Подтверждает платёж
5. Статус обновляется автоматически

```html

```

### 2.3 Электронные кошельки

## ЧАСТЬ 3: РАССРОЧКИ И КРЕДИТЫ

### 3.1 Почему рассрочки критичны

50%+ покупателей электроники, 30%+ мебели, 20%+ одежды — в рассрочку. Без рассрочки вы теряете до половины конверсии в средний и высокий чек.

### 3.2 Виды рассрочек

| Тип | Описание | Провайдеры |
|-----|----------|------------|
| Рассрочка 0% | Без переплаты, 4-24 месяца | Долями, Halva, Совесть |
| Кредит | С процентом, 12-60 месяцев | Тинькофф, Сбер, Альфа |
| BNPL (Buy Now Pay Later) | 4 платежа, 0% | Долями, Split |

### 3.3 UX интеграция рассрек

**На карточке товара:**

## ЧАСТЬ 4: ФИСКАЛИЗАЦИЯ ПО 54-ФЗ

### 4.1 Обязательные требования

Каждый платёж в интернете должен быть фискализирован:
- Онлайн-касса (ККТ) для каждого платежа
- Электронный чек отправляется на email/телефон
- Чек содержит: наименование, цену, НДС, способ оплаты

### 4.2 Провайдеры фискализации

- Яндекс.Касса (ЮKassa)
- CloudPayments
- Робочек
- Атол

### 4.3 UX паттерн чека

```html
<div class="receipt-request">
  <label>
    Email для получения чека:
    <input type="email" placeholder="email@example.com" required>
  </label>
  <span class="note">Электронный чек будет отправлен согласно 54-ФЗ</span>
</div>
```

## ЧАСТЬ 6: ЧЕКАУТ-ПОТОК

### 6.1 Оптимальный чекаут для РФ

1. **Корзина** -> Проверка товаров
2. **Данные покупателя** -> Имя, телефон, email
3. **Доставка** -> Выбор способа и адреса
4. **Оплата** -> Выбор метода, ввод данных
5. **Подтверждение** -> Итого, чек, статус

### 6.2 Отличия от западного чекаута

| Параметр | Западный | Российский |
|----------|----------|------------|
| Шагов | 3-4 (или 1-page) | 4-5 (или 1-page) |
| Регистрация | Guest checkout | Телефон + SMS подтверждение |
| Адрес | Автозаполнение Google | Яндекс.Карты / 2GIS |
| Доставка | Почта / курьер | ПВЗ + курьер + самовывоз |
| Оплата | Карта / PayPal | Карта / СБП / рассрочка / наличные |

### 6.3 SMS-подтверждение

Вместо email+password — телефон+SMS:
```html
<div class="phone-auth">
  <label>Номер телефона</label>
  <input type="tel" placeholder="+7 (___) ___-__-__">
  <button>Получить код</button>
  <!-- После ввода кода: -->
  <div class="sms-code">
    <input type="text" maxlength="4" placeholder="Код из SMS">
  </div>
</div>
```

## ЧАСТЬ 7: АВТОПЛАТЕЖИ И РЕКУРРЕНТ

### 7.1 Автоплатежи в РФ

Подписочная модель в РФ развивается, но с особенностями:
- Автоплатёж через СБП — растущий тренд
- Привязка карты — стандартный метод
- SberPay автоплатёж — для подписок Сбера
- Тинькофф автоплатёж — для подписок Тинькофф

**UX паттерн:**
```html
<div class="autopay-toggle">
  <label>
    <input type="checkbox" checked> Автоматическое продление подписки
  </label>
  <p class="hint">Списание 990 ₽/мес автоматически. Отменить в любое время.</p>
</div>
```

**Правила для РФ:**
- Автоплатёж по умолчанию ВКЛЮЧЁН (opt-out, не opt-in) — юридически допустимо
- Ясное уведомление о следующем списании
- Простой механизм отмены (2 клика, не 5)
- Уведомление за 1 день до списания (закон о потребительском кредите)

## ЧАСТЬ 9: SBERPAY — ДЕТАЛЬНЫЙ РАЗБОР

### 9.1 SberPay UX flow

SberPay — оплата по номеру телефона без ввода данных карты:

1. Пользователь выбирает «SberPay»
2. Вводит номер телефона (привязан к Сберу)
3. Получает push-уведомление в СберБанк Онлайн
4. Подтверждает платёж в приложении Сбера
5. Статус обновляется автоматически

```html
<div class="sberpay-method">
  <div class="method-header">
    <img src="sberpay-logo.svg" alt="SberPay">
    <span>Оплата по номеру телефона</span>
  </div>
  <div class="phone-input">
    <input type="tel" placeholder="+7 (___) ___-__-__">
    <p class="hint">Номер телефона, привязанный к СберБанк Онлайн</p>
  </div>
  <button class="sberpay-btn">Оплатить через SberPay</button>
</div>
```

### 9.2 Преимущества SberPay для UX

- Не нужно вводить данные карты (конверсия +15-25%)
- Нет страха ввода данных карты (доверие к Сберу)
- Мгновенное подтверждение
- Работает на всех устройствах

## ЧАСТЬ 11: ПРАВИЛА ЦЕНООБРАЗОВАНИЯ И ИНТЕГРАЦИИ SMMplan

### 11.1 Pricing Model Rules
- Провайдеры хранят `rate` в USD за 1000 штук.
- В каталоге (`src/actions/order/catalog.ts`) вычисляются два поля:
  - `pricePer1kRub` = `rate × markup × usdToRub` — розничная цена за 1000 шт в рублях.
  - `pricePerUnitRub` = `pricePer1kRub / 1000` — цена за 1 штуку.
- В UI пользователь ВСЕГДА видит цену за 1 штуку (`pricePerUnitRub`), подпись: `₽ / шт`.
- Запрещено писать в UI `/ 1000 шт` или показывать `pricePer1kRub` напрямую пользователю.
- Запрещено вручную делить `pricePer1kRub / 1000` в компонентах — использовать `pricePerUnitRub`.

### 11.2 Payment Gateways Rules
- API запросы выполняются ВСЕГДА: Запрещено локально имитировать/заглушать или делать моковые перенаправления на `/api/dev/mock-payment` при пополнении баланса или оплате заказов, если в панели администратора настроены любые реквизиты шлюза.
- В среде разработки, если боевые ключи содержат плейсхолдеры, но настроены тестовые ключи шлюза, система обязана автоматически переключиться на тестовые реквизиты.

### 11.3 Provider Synchronization
- Shadow Catalog (Теневой буфер): все каталоги провайдеров сохраняются в Redis-кэш (`provider:{id}:catalog`).
- Cherry-Pick Import: в БД `Service` попадают только выбранные админом вручную услуги.
- Auto-Pricing Engine: Margin Worker пересчитывает розничную цену при подорожании у провайдера для сохранения процента маржи.
- Zombie Eraser: ночная синхронизация помечает услуги как `isActive = false`, если провайдер удалил их.


## Step-by-step execution protocol

1. **Identify payment methods:** Определить нужные методы (карты, СБП, рассрочка, наличные)
2. **Design checkout flow:** Спроектировать поток с учётом РФ специфики
3. **Add installment calculator:** Добавить калькулятор рассрочки для чеков > 5000 руб
4. **Setup SBP QR:** Настроить отображение QR-кода для СБП
5. **Add receipt email:** Поле email для чека по 54-ФЗ
6. **B2B fields:** Добавить ИНН с автозаполнением для B2B
7. **Phone auth:** Заменить email-регистрацию на телефон+SMS
8. **Payment icons:** Показать все поддерживаемые методы (МИР, СБП, рассрочка)
9. **Test with real payments:** Протестировать каждый платёжный метод

## Scope boundaries

### DOES
- Проектировать чекаут-поток для российского рынка
- Рекомендовать платёжные методы и их интеграцию
- Настраивать UX рассрочек и кредитов
- Проектировать B2B оплату с ИНН
- Рекомендовать фискализацию по 54-ФЗ

### DOES NOT
- Настраивать платёжные шлюзы технически (ЮKassa, CloudPayments)
- Подключать онлайн-кассу (только рекомендации)
- Юридическая консультация по 54-ФЗ
- Настраивать DaData API (только рекомендации по UX)

## Error handling

| Scenario | Response |
|----------|----------|
| Нет рассрочки при чеке > 10 000 руб | Добавить рассрочку — потеря до 50% конверсии без неё |
| Нет СБП как метод оплаты | Добавить — растущий метод, +15-20% конверсии для мобильных |
| Нет оплаты наличными | Добавить для регионов — значимая доля, особенно вне Москвы |
| B2B не может оплатить по ИНН | Добавить автозаполнение по ИНН через DaData |
| Нет чека по 54-ФЗ | Критично — штрафы, добавить email для чека обязательно |
