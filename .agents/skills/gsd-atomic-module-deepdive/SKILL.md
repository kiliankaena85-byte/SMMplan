# 🏛️ Скилл: GSD Atomic Module Deep-Dive & Academic Verification

## 🎯 Назначение и Философия

Когда искусственный интеллект пытается спроектировать крупную систему или обучить саппорт «за один большой промпт», он неизбежно создает **поверхностный каркас** с заглушками (// TODO, «и так далее»), потому что ограниченное контекстное окно не позволяет детализировать каждый пункт.

**Этот скилл предписывает железный протокол:**
Любая масштабная задача, документация, обучающая база или архитектура разбивается на **автономные атомарные модули**, и каждый модуль прорабатывается **последовательно, изолированно и досконально**, не теряя контекст и не допуская поверхностности.

---

## 🧭 4 Неделимых Слоя каждого Модуля (Dual-Core 4-Layer Audit)

Каждый модуль ОБЯЗАН быть проработан на стыке 4 слоев:

1. ⚙️ **Code Ground Truth (Реальность движка):** Сверка с реальной БД PostgreSQL, Prisma, Server Actions, очередями BullMQ, API шлюзами. Никаких выдуманных функций!
2. ⚖️ **Legal & CFO Guard (Право и Финансы):** Жесткий комплаенс: 152-ФЗ, 54-ФЗ, 402-ФЗ, ЗоЗПП, ст.782 ГК РФ, защита маржи, лимиты баланса SupportBalancePolicy.
3. 💬 **Dual-Core Scripts (Маркетинг + Право):** Готовые скрипты для саппорта: симбиоз заботы о клиенте и бронебойной юридической защиты без серого сленга.
4. 🧪 **Proof of Correct (Верификация & Память):** Автотесты Vitest, Typecheck tsc, интерактивный тренажер, скриншоты UI и сохранение в долговременную память RAG.

## 🔄 Пошаговый Протокол Исполнения (Ralph Loop Pipeline)

### Шаг 1: Формирование Дорожной Карты (Decomposition)
1. Задача разбивается на N пронумерованных изолированных модулей (например, Модули 1–6).
2. Создается Матрица Прогресса.

### Шаг 2: Атомарная Итерация (Atomic Focus)
1. Агент берет **СТРОГО ОДИН МОДУЛЬ**.
2. Исследует относящийся к нему код через view_file и grep_search.
3. Моделирует все пограничные случаи (Edge Cases), сбои, мошенничество и правовые риски.
4. Создает подробное, законченное описание без сокращений («etc.», «и т.д.» запрещены).

### Шаг 3: Согласование и Внедрение в Код (Integration)
1. Код, база данных или сценарии обучающей академии (src/data/support-training-scenarios.ts) обновляются реальными данными.
2. Проводятся тесты: npm test и npx tsc --noEmit.

### Шаг 4: Фиксация в Памяти и Переход (Checkpoint & Next)
1. Результаты фиксируются в walkthrough.md и в GraphRAG (POST http://localhost:8100/api/decision).
2. В Матрице Прогресса статус меняется на [x] Выполнено.
3. Агент переходит к следующему модулю с чистым, сфокусированным контекстом.
