## 2. Внесённые правки

### FIX-1 · `perf(db)` — индексы для горячих путей · `fd393b4f`

**Проблема.** `src/bot/index.ts` на **каждое** входящее обновление Telegram делает `db.user.findFirst({ where: { telegramId, tenantId } })` — 10+ мест; два админ-счётчика добавляют `db.user.count({ where: { telegramId: { not: null }, tenantId } })`. Индекса на `telegramId` не было вообще → последовательное сканирование самой большой таблицы. Модель `Provider` **не имела ни одного индекса**, при этом провайдеры фильтруются по `isActive` в 19 местах (админ-списки, воркеры синхронизации, роутинг/фолбэк).

**Что сделано.**
| Файл | Изменение |
|---|---|
| `prisma/schema.prisma` | `User @@index([telegramId, tenantId])`, `Provider @@index([isActive])` |
| `prisma/migrations/20260923090000_add_hot_path_indexes/migration.sql` | идемпотентные `CREATE INDEX IF NOT EXISTS` (применится через `prisma migrate deploy`) |
| `prisma/migrations/apply_indexes_hot_paths_CONCURRENTLY.sql` | zero-downtime вариант для больших прод-таблиц: `CREATE INDEX CONCURRENTLY` (Prisma не умеет это внутри своей транзакции) + порядок действий через `prisma migrate resolve --applied` |

**Почему составной индекс `(telegramId, tenantId)`:** он покрывает оба шаблона — с тенантом (большинство вызовов) и без него (префикс по `telegramId`).

**Проверка.** Схема по-прежнему парсится (87 моделей / 12 enum), индексы попали в нужные модели (User — строка 124, Provider — 399), `tsc` без новых замечаний. **Не проверено:** план запроса и ускорение — нужен `EXPLAIN ANALYZE` на stage:
```sql
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM "User" WHERE "telegramId" = '...' AND "tenantId" = 'smmplan';
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM "Provider" WHERE "isActive" = true;
```
**Риск:** низкий — индексы аддитивны, идемпотентны; цена — небольшой рост времени записи. Откат: `DROP INDEX CONCURRENTLY IF EXISTS "User_telegramId_tenantId_idx";` + revert коммита.

**Проверка.** Контраст посчитан по значениям токенов (до/после). **Требует stage:** визуальная проверка в браузере, что оттенок не «вылезает» из бренда.
