# gsd-russian-legal-watchdog

Этот скилл предназначен для проверки кодовой базы, страниц и юридических документов проекта Smmplan на соответствие актуальному законодательству Российской Федерации.

---

## When to activate

| Триггер / Событие | Описание необходимости |
|---|---|
| Перед релизом проекта в продакшн | Проверка корректности реквизитов и согласий на обработку ПД |
| При изменении платежных шлюзов | Контроль передачи параметров чеков согласно 54-ФЗ |
| При обновлении форм ввода (регистрация, заказ, поддержка) | Проверка чекбоксов и дисклеймеров ФЗ-152 |
| По запросу пользователя о юридическом аудите | Запуск полного сканирования сайта |

---

## Scope boundaries

Этот скилл проверяет технические и текстовые маркеры соответствия законодательству РФ на веб-интерфейсе и в коде.

**Входит в область проверки (In scope):**
- Наличие страниц публичной оферты, политики конфиденциальности, условий возврата.
- Отсутствие шаблонных скобок `[...]` и меток автозамены в текстах юридических соглашений.
- Наличие дисклеймеров о согласии с обработкой персональных данных рядом с кнопками отправки форм.
- Отображение юридических реквизитов (ИНН, ОГРН/ОГРНИП) в футере.

**Вне области проверки (Out of scope):**
- Проверка юридической силы документов в суде.
- Проверка реальной постановки кассы на учет в ФНС (только факт отправки данных шлюзу).
- Налоговый и бухгалтерский учет (для этого используйте `gsd-russian-accounting-watchdog`).

## Step-by-step execution protocol

### Шаг 1 — Запуск автоматизированного сканера
Запустите скрипт проверки соответствия в корневой папке проекта:
```bash
node .agent/skills/gsd-russian-legal-watchdog/scripts/check-compliance.js
```

### Шаг 2 — Анализ отчета соответствия
Скрипт выведет список проверок в формате:
- `[PASS]` — проверка пройдена успешно.
- `[WARN]` — некритичное замечание (например, захардкоженные реквизиты).
- `[FAIL]` — критическая ошибка соответствия (например, отсутствие политики).

### Шаг 3 — Устранение нарушений
1. При обнаружении ошибок `[FAIL]` в юридических текстах — замените заглушки `[...]` на реальные реквизиты через `SettingsProvider`.
2. При отсутствии дисклеймеров в формах — добавьте текстовое предупреждение со ссылками на `/legal/privacy` и `/legal/terms` под кнопкой отправки формы.

### Шаг 4 — Финальная верификация
Повторно запустите скрипт проверки и убедитесь в получении статуса `AUDIT SUCCESS` (код возврата `0`).

## Error handling

| Проблема / Ошибка | Действие ассистента |
|---|---|
| Скрипт `check-compliance.js` не найден | Проверить наличие файла в папке `scripts/` и восстановить его структуру |
| Ошибка выполнения Node.js | Проверить синтаксис скрипта и наличие необходимых модулей (используются только базовые модули `fs` и `path`) |
| Обнаружен статус `AUDIT FAILED` | Проанализировать лог ошибок, внести правки в соответствующие файлы и повторить проверку |
