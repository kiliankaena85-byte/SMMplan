# Client Preference Interview — структурированный опрос

## When to activate

- Начинается работа с новым клиентом и нужно понять предпочтения
- Пользователь собирается показывать референсы без опроса
- Нужно провести визуальную калибровку (9-скриншот тест)
- Клиент просит «сделайте мне красивый сайт» без конкретики
- Перед запуском дизайн-спринта

## ПРОТОКОЛ ОПРОСА В 4 РАУНДА

### РАУНД 1: Ориентация (5 минут)
Агент задаёт вопросы ТОЛЬКО по бизнесу, НЕ по дизайну:

Q1: «Опишите своего идеального клиента одним предложением. Не демография — а ситуация: что он делает прямо сейчас без вашего продукта?»

Q2: «Назовите три конкурента. Для каждого скажите: что они делают лучше вас, и что хуже.»

Q3: «Если бы ваш бренд был человеком — кем бы он был? Профессия, характер, стиль одежды.»

Q4: «Что НЕ должен подумать пользователь, увидев ваш сайт?»

### РАУНД 2: Визуальная калибровка (10 минут)
Агент показывает 9 скриншотов сайтов в 3x3 сетке. НЕ конкурентов — просто разные стили:

ROW 1: Editorial / Brutalist / Glassmorphism
ROW 2: Minimalist / Data-dense / Playful
ROW 3: Corporate / Premium / Experimental

Вопросы к каждому скриншоту:
- «Это вам нравится? Почему ДА или ПОЧЕМУ НЕТ?»
- «Ваш пользователь будет доверять этому стилю?»
- «Это слишком смело / слишком консервативно для вашей ниши?»

### РАУНД 3: Референс-анализ (15 минут)
Агент показывает КОНКУРЕНТОВ с аннотациями:
- Что они хотят, чтобы вы сделали
- Почему это работает технически
- Что в этом не работает
- Применимо ли это к вам?

### РАУНД 4: Feasibility Check (5 минут)
ПОСЛЕ опроса — агент проверяет реализуемость:
- [ ] Есть ли у нас контент для этого?
- [ ] Технически реализуемо в нашем стеке?
- [ ] Соответствует ли нашему бренд-гайду?
- [ ] Не противоречит ли нашему позиционированию?
- [ ] Есть ли бюджет на это?

## Step-by-step execution protocol

1. **Prepare**: Проверить brain/ на наличие предыдущих интервью с этим клиентом
2. **Round 1 — Business**: Задать 4 бизнес-вопроса, зафиксировать ответы
3. **Round 2 — Visual calibration**: Сгенерировать 9-скриншот сетку через Browser Agent
4. **Collect reactions**: Зафиксировать что нравится и что отталкивает
5. **Round 3 — Reference analysis**: Показать конкурентов с аннотациями (5-слойные карточки)
6. **Round 4 — Feasibility**: Проверить реализуемость каждого понравившегося элемента
7. **Synthesize**: Сформировать визуальный профиль клиента
8. **Save to brain/**: Записать результаты в `.gemini/antigravity/brain/client-preferences/`

## Scope boundaries

### DOES
- Проводить структурированный опрос в 4 раунда
- Собирать визуальные предпочтения через 9-скриншот тест
- Анализировать конкурентов с аннотациями
- Проверять реализуемость понравившихся решений
- Сохранять результаты в персистентную память

### DOES NOT
- Показывать референсы БЕЗ предварительного опроса
- Навязывать свои предпочтения вместо предпочтений клиента
- Пропускать раунды для экономии времени
- Завершать опрос без feasibility check

## Error handling

| Scenario | Response |
|----------|----------|
| Клиент не может выбрать из 9 скриншотов | Сузить до 3 финалистов, задать бинарные вопросы |
| Клиент выбирает противоречивые стили | Указать противоречие, попросить приоритизировать |
| Нет скриншотов конкурентов | Использовать Browser Agent для захвата, или попросить URL |
| Клиент торопится | Минимум Раунд 1 + Раунд 2, остальные по желанию |
