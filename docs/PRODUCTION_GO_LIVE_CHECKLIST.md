### 2. Ручное тестирование пользовательского пути (E2E Manual Testing)

#### Сценарий А. Быстрый заказ без авторизации (Guest Checkout)
- [ ] Открыть лендинг `smmplan.pro` в режиме инкогнито.
- [ ] Выбрать соцсеть (Telegram) → Категорию (Подписчики) → Услугу.
- [ ] Убедиться, что поле количества заполнено минимальным значением (`minQty`), а цена указана в формате **`... ₽ / шт`**.
- [ ] Ввести ссылку на открытый канал и тестовый email.
- [ ] Нажать кнопку «Перейти к оплате» — убедиться, что открывается шлюз ЮKassa.
- [ ] Попробовать нажать кнопку с пустым полем ссылки — убедиться, что срабатывает `animate-shake` и скролл к ошибке (кнопка не заблокирована).

#### Сценарий Б. Пополнение баланса и заказ из Личного Кабинета
- [ ] Авторизоваться по Email и через Telegram.
- [ ] Зайти в раздел «Пополнить баланс» (`/dashboard/add-funds`).
- [ ] Создать платеж на 100 ₽ через СБП/карту.
- [ ] Убедиться, что после оплаты баланс в шапке обновился мгновенно.
- [ ] Оформить заказ с баланса — убедиться, что списание прошло с точностью до копейки.

#### Сценарий В. Обработка частичных выполнений и отмен (Refund Test)
- [ ] При отмене заказа убедиться, что 100% средств возвращаются на баланс моментально.
- [ ] При статусе `PARTIAL` проверить, что возврат рассчитан строго за недоставленный остаток.

#### Сценарий Г. Мультитенантность и Витрина SMMflux (`smmflux.ru`)
- [ ] Открыть витрину `smmflux.ru` — проверить неоновую тему (Radiant Aurora), компоненты `<FluxButton>`, `<BorderBeam>`.
- [ ] Убедиться, что заказы с SMMflux помечаются тенантом `flux`.

# 🛑 ЧАСТЬ 3. АВАРИЙНЫЕ ПРОТОКОЛЫ (Emergency Runbook)

### 1. Кнопка экстренной остановки (Killswitch)
* При обнаружении аномального списания или сбоя внешнего шлюза:
  1. В админ-панели перейти во вкладку **Настройки** → **Аварийный режим**.
  2. Активировать **Emergency Provider Pause** (прием заказов ставится на паузу в статус `PENDING_CHECK` без отправки поставщику).

### 2. Откат релиза (Rollback Protocol)
* В случае критической ошибки фронтенда:
  ```bash
  git checkout <предыдущий_стабильный_коммит>
  npm run build
  docker-compose up -d --build web
  ```
