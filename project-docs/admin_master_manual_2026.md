# 1. СИСТЕМНАЯ ТОПОЛОГИЯ И МАКРО-АРХИТЕКТУРА

Платформа SMMpanel 1.0 спроектирована как **отказоустойчивый распределенный комплекс**, разделенный на 5 ключевых слоев:

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                 1. СЛОЙ ВХОДЯЩЕГО ТРАФИКА                                        │
│               smmplan.pro (B2B Клиенты)            smmflux.ru (B2C Клиенты)                      │
│                                           │                                                      │
│                                           ▼                                                      │
│                        Cloudflare Tunnel & DDoS Protection                                       │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                 2. СЛОЙ МАРШРУТИЗАЦИИ И СЕССИЙ                                   │
│  Next.js 16 Edge Middleware (src/middleware.ts):                                                 │
│  • Анализ заголовка Host -> Автоматическое определение бренда (smmplan / flux)                   │
│  • Очистка спуфинговых заголовков -> Установка доверенного x-tenant-id                           │
│  • RBAC Guard: Защита админ-маршрутов (/admin/*) на основе ролей StaffRole                       │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                 3. БИЗНЕС-ЛОГИКА И СЕРВЕРНЫЕ ДЕЙСТВИЯ                            │
│  • WalletOps Service: Неизменяемый расчет балансов, списания, возвраты, начисление бонусов       │
│  • LinkAnalyzer Engine: Очистка UTM/трекеров, ReDoS-аудит, сопоставление с каталогом             │
│  • Gemini 3 Flash Adapter: Генерация безопасных регулярных выражений и автотестов                │
│  • VaultService: Хранение ключей эквайрингов и API в зашифрованном виде (AES-256-GCM)            │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                 4. АСИНХРОННЫЕ ОЧЕРЕДИ (REDIS BULLMQ)                            │
│  • order-dispatch-queue: Отправка заказов провайдерам (5 воркеров, retry 3x)                     │
│  • order-status-sync-queue: Опрос статусов активных заказов каждые 60 секунд                     │
│  • refill-sync-queue: Мониторинг гарантийных докруток                                            │
│  • provider-price-sync-queue: Ежедневный мониторинг цен поставщиков (в 03:00 МСК)                │
├──────────────────────────────────────────────────────────────────────────────────────────────────┤
│                                 5. ХРАНИЛИЩЕ ДАННЫХ (POSTGRESQL 16)                              │
│  • Изоляция на уровне строк (Row-Level Partitioning по tenantId)                                 │
│  • Финансовый триггер block_ledger_mutation() (запрет UPDATE/DELETE в LedgerEntry)               │
│  • Каскадная защита onDelete: Restrict (невозможно случайно удалить услугу с историей заказов)   │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

# 2. РЕВЕРС-ИНЖИНИРИНГ И ЭТАЛОНЫ

При проектировании платформы были использованы лучшие инженерные решения мировых лидеров:

| Параметр архитектуры | Как сделано в старых SMM-скриптах | Как сделано в SaaS-эталонах (Shopify, Stripe) | **Решение SMMpanel 1.0 (2026)** |
| :--- | :--- | :--- | :--- |
| **Импорт каталогов поставщиков** | Импорт 5000+ услуг напрямую в БД &rarr; база раздувается, тормозит | Буферизация прайс-листов | **Redis Shadow Catalog**: Каталог поставщика буферизуется в Redis, в PostgreSQL админ импортирует только нужные услуги. |
| **Финансовый учет** | Прямой `UPDATE user.balance` &rarr; нет истории, риск взлома | Двойная запись (Ledger) и Idempotency Keys | **Неизменяемый LedgerEntry**: Баланс меняется только встречными проводками через триггер БД. |
| **Мульти-магазин** | Отдельная копия скрипта на каждый сайт | Multi-Store Row-Level Partitioning | **Единый Бэкенд**: 2 сайта работают из одной кодовой базы и одной БД с изоляцией по `tenantId`. |
| **Анализ ссылок** | Примитивный поиск `strpos("t.me")` &rarr; частые ошибки заказов | Строгий парсинг с AST-аудитом | **LinkAnalyzer + ReDoS Guard**: Авто-очистка мусорных меток и AI-генерация правил через Gemini 3 Flash. |
| **Ценообразование** | Умножение цены на 1000 на клиенте (`$ / 1k`) &rarr; путаница | Прозрачная юнит-экономика за 1 шт | **Strictly ₽ / шт**: Все расчеты и интерфейс работают строго в формате розничной цены за 1 единицу. |

# 3. МУЛЬТИ-ТЕНАНТНОСТЬ: SMMPLAN (B2B) VS SMMFLUX (B2C)

Платформа обслуживает строго 2 бренда из единого ядра:
* **SMMplan** (`smmplan.pro`) — B2B сервис (счета для юрлиц, договор-оферта, строгие таблицы).
* **SMMflux** (`smmflux.ru`) — B2C сервис (дизайн Radiant Aurora, чекаут в 1 клик, геймификация).

### 3.1. Матрица Разделения Данных:
* **🌐 Глобальные (Общие)**: Балансы провайдеров API, ключи ЮKassa/CryptoBot, Gemini AI, штат сотрудников саппорта.
* **🔒 Изолированные (Раздельные)**: Клиенты (`User.tenantId`), Заказы (`Order.tenantId`), Балансы в ЛК, Тикеты, Промокоды.

# 4. ГДЕ И КАК НАСТРАИВАТЬ ПЛАТЕЖНЫЕ СИСТЕМЫ

Все платежные интеграции настраиваются в разделе **`/admin/settings`** во вкладке **«Платежные Шлюзы»**.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    ПОШАГОВАЯ НАСТРОЙКА ПЛАТЕЖНЫХ ШЛЮЗОВ                     │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. Перейдите в раздел /admin/settings -> вкладка "Платежные шлюзы"          │
│ 2. Выберите нужный шлюз (ЮKassa / CryptoBot / Robokassa / B2B Счета)        │
│ 3. Введите API-ключи -> Нажмите [💾 Сохранить настройки]                    │
│ 4. Ключи мгновенно зашифруются алгоритмом AES-256-GCM в Vault-хранилище    │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 📋 Пошаговые инструкции по каждому платежному методу:

* **💳 Подключение ЮKassa (СБП, Карты РФ, T-Pay, Mir Pay)**:
  1. Откройте `/admin/settings` &rarr; карточка **«ЮKassa»**.
  2. В поле `Shop ID` вставьте идентификатор магазина из личного кабинета ЮKassa.
  3. В поле `Секретный ключ (Secret Key)` вставьте боевой ключ API (начинается с `live_...`).
  4. Переключатель **«Тестовый режим»** переведите в положение `ВЫКЛ`.
  5. Нажмите `[💾 Сохранить]` &rarr; статус шлюза загорится зеленым `🟢 Активен`.
* **🤖 Подключение CryptoBot (USDT, TON, BTC)**:
  1. В `/admin/settings` откройте блок **«CryptoBot»**.
  2. Вставьте API Token от `@CryptoBot`.
  3. Нажмите `[💾 Сохранить]` &rarr; клиентам станет доступна кнопка оплаты криптовалютой.
* **⚡ Подключение Robokassa (Резервный эквайринг)**:
  1. Введите `Логин Магазина`, `Пароль #1` (для инициализации) и `Пароль #2` (для вебхуков).
* **📄 Настройка B2B-Счетов (Безнал для ООО и ИП)**:
  1. Откройте вкладку **«Реквизиты Компании»**.
  2. Заполните: Название, ИНН, КПП, ОГРН, БИК банка, Расчетный счет и Корр. счет.
  3. Загрузите скан факсимиле подписи и печати (PNG).
  4. При выборе юрлицом безналичной оплаты система автоматически сгенерирует готовый PDF-счет с печатью.

### ⚖️ Налоговый Автомат 54-ФЗ (Редакция 2026):
* **Базовая ставка НДС**: 22% (п. 3 ст. 164 НК РФ, ФЗ № 425-ФЗ).
* **Порог УСН**: 20 000 000 ₽ (п. 1 ст. 145 НК РФ, ФЗ № 176-ФЗ / 425-ФЗ).
* До 20 млн ₽ чеки ЮKassa уходят с `vat_code: 1` (Без НДС). При превышении касса сама переключается на `vat_code: 10` (НДС 22%).

# 5. ГДЕ И КАК ДОБАВЛЯТЬ ПРОВАЙДЕРОВ API

Управление поставщиками сосредоточено в 3 экранах:
* **`/admin/providers`** — мониторинг балансов, добавление шлюзов и проверка пинга.
* **`/admin/providers/import`** — выборочный (Cherry-Pick) импорт услуг.
* **`/admin/providers/routes`** — настройка резервных маршрутов (Failover).

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    ПОШАГОВОЕ ДОБАВЛЕНИЕ НОВОГО ПРОВАЙДЕРА                   │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. Откройте /admin/providers -> Нажмите кнопку [+ Добавить Провайдера]      │
│ 2. Введите URL API поставщика и API-ключ -> Выберите протокол SMM API v2    │
│ 3. Нажмите [Проверить соединение и сохранить]                               │
│ 4. Система сделает тестовый вызов action: "balance" и покажет статус HEALTHY│
└─────────────────────────────────────────────────────────────────────────────┘
```

### 🚦 Справочник Аварийных Индикаторов Шлюзов:
* `🟢 HEALTHY`: Шлюз работает штатно, пинг $< 800$ мс, баланс в норме.
* `🔴 OUT_OF_BALANCE`: Депозит у поставщика $< \$10.00$. Заказы встают на авто-паузу `PENDING_RETRY`.
* `🟡 PRICE_DRIFT`: Скачок цены $> 30\%$. Услуга автоматически переводится в Карантин `/admin/catalog/quarantine`.
* `⚠️ TIMEOUT (504)`: Сервер поставщика не отвечает. Очередь BullMQ делает 3 попытки и переключает на резервный шлюз.

# 6. АНАЛИЗАТОР ССЫЛОК, REDOS-GUARD И GEMINI AI

Конвейер распознавания ссылок работает в 5 этапов:
1. **Сырой URL**: Клиент вставляет ссылку из приложения с метками (`?si=...`, `?igsh=...`, `?utm_source=...`).
2. **`UrlCleaner`**: Срезает трекеры, схлопывает `m.vk.com` $\to$ `vk.com`, `youtu.be` $\to$ `youtube.com`, нормализует `@durov` $\to$ `t.me/durov`.
3. **`ReDoS Guard`**: AST-аудит блокирует опасные регулярные выражения с вложенными квантификаторами `(a+)+`.
4. **`LinkAnalyzer`**: Определяет соцсеть и тип объекта (`CHANNEL`, `POST`, `STORY`, `REELS`, `COMMENT`).
5. **`Order Wizard`**: Оставляет в выпадающем списке только совместимые услуги.

# 7. ПОЛНЫЙ АТЛАС ВСЕХ 18 ЭКРАНОВ

---

### 7.1. `/admin/dashboard` — Главный Аналитический Пульт
* **Назначение**: Оперативный мониторинг ключевых показателей выручки, маржи и здоровья шлюзов.
* **Метрики**: *Выручка за сегодня* (по `LedgerEntry`), *Чистая Маржа* (выручка минус себестоимость), *Заказов в работе*, *Здоровье Шлюзов* (HEALTHY).
* **Кнопки**: `[🔄 Обновить данные]`, `[📅 Фильтр периода]`.

---

### 7.2. `/admin/orders` — Реестр Заказов, Перезапуск и Возвраты
* **Назначение**: Центральный журнал управления заказами.
* **Столбцы**: ID, Клиент, Услуга/Ссылка, Кол-во/Остаток, Сумма (₽), Статус.
* **Кнопки действий**:
  * `[🔄 Перезапустить (Retry)]`: Сбрасывает статус в `PENDING` и отправляет в BullMQ повторно (деньги повторно НЕ списываются).
  * `[🚫 Отменить с возвратом]`: Статус `CANCELED`, 100% возврат на баланс в ЛК через `WalletOps.refund()`.
  * `[✂️ Частичный возврат]`: Считывает остаток `remains` и возвращает деньги за невыполненный объем.
  * `[📥 Экспорт в CSV]`: Выгрузка отфильтрованных заказов в Excel.

---

### 7.3. `/admin/orders/[id]` — Карточка Заказа и Лог Шлюза
* **Назначение**: Полный аудит выполнения заказа.
* **Секции**: Посекундный таймлайн жизненного цикла, сырой JSON-ответ провайдера (`bad_link`, `order_id`), блок ручной смены шлюза.

---

### 7.4. `/admin/refills` — Гарантийные Докрутки и Синхронизация
* **Назначение**: Контроль выполнения гарантийных докруток при отписках.
* **Столбцы**: ID докрутки, ID родительского заказа, начальный счетчик (Start Count), статус (`REFILLING`, `COMPLETED`).
* **Кнопки**: `[🔄 Синхронизировать]`, `[🚫 Отклонить заявку]`.

---

### 7.5. `/admin/tickets` — Омниканальный Тикет-Центр и SLA
* **Назначение**: Рабочее место операторов поддержки.
* **Функции**: SLA-таймеры (зеленый: $< 15$ мин, красный: $> 30$ мин), приоритеты (`LOW`, `MEDIUM`, `HIGH`, `URGENT`), статусы `OPEN`, `WAITING_USER`, `RESOLVED`.

---

### 7.6. `/admin/tickets/[id]` — Диалог с Клиентом и Шаблоны Ответов
* **Назначение**: Чат с клиентом по конкретному обращению.
* **Кнопки**: `[⚡ Быстрые шаблоны ответов]` (13 типовых ответов в 1 клик), `[⬆️ Эскалировать на Старшего]`, `[✅ Решить и закрыть]`.

---

### 7.7. `/admin/catalog` — Управление Соцсетями, Услугами и Ценами

#### 🎯 Назначение экрана:
Управление витриной каталога, формирование розничных цен strictly в формате `₽ / шт`, настройка параметров гарантии, скорости и лимитов заказа.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 КАК УПРАВЛЯТЬ СОЦСЕТЯМИ, КАТЕГОРИЯМИ И УСЛУГАМИ             │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. ВЫБОР СОЦСЕТИ: Верхние табы в /admin/catalog (Telegram / VK / Instagram) │
│ 2. ВЫБОР КАТЕГОРИИ: Группы услуг (Подписчики / Лайки / Просмотры / Репосты) │
│ 3. НАСТРОЙКА УСЛУГИ: Клик на [✏️ Редактировать] -> Наценка, лимиты, бейджи │
│ 4. ВЫВОД ИЗ ОБОРОТА: Клик на [📦 Архивировать] -> Скрывается с сайта        │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### 📋 Пошаговые сценарии:
* **Сценарий 1: Переключение соцсети (Network)**: Кликните на нужную вкладку: `Telegram`, `VK`, `Instagram`, `YouTube`, `TikTok`, `Rutube`.
* **Сценарий 2: Изменение наценки и цены**:
  1. Нажмите кнопку **`[✏️ Редактировать]`** напротив услуги.
  2. Укажите множитель наценки (например, `2.50` для наценки 150%).
  3. Система покажет: *«Оптовая: $0.10/1k &rarr; Розничная на сайте: 0.0238 ₽/шт»*.
  4. Нажмите `[💾 Сохранить изменения]`.
* **Сценарий 3: Настройка бейджей (Гарантия, Скорость)**:
  * В окне редактирования отметьте галочку `🛡 Гарантия 30 дней` и бейдж `⚡ До 50 000 в сутки`.
* **Сценарий 4: Вывод из оборота (Safe Archive)**:
  * Нажмите `[📦 Архивировать]` &rarr; услуга скроется с витрины (`isActive: false`), но история заказов сохранится.

#### 💰 Формула Ценообразования:
$$\text{Розничная Цена (₽/шт)} = \frac{\text{ProviderRate (\$) } \times \text{MarkupMultiplier} \times \text{ExchangeRate (USD/RUB)}}{1000}$$

# 8. МАРКЕТИНГОВЫЙ ДВИЖОК: ПАРТНЕРКА

Реферальный процент (5% $\to$ 7% $\to$ 10% $\to$ 15%) начисляется **СТРОГО ОТ ЧИСТОЙ МАРЖИ**:
$$\text{PartnerBonusRub} = (\text{OrderPriceRub} - \text{ProviderCostRub}) \times \text{ReferralPercent}$$
*Пример*: Заказ 1000 ₽, себестоимость 600 ₽ $\to$ Маржа 400 ₽ $\to$ Партнер 10% получает **40 ₽** (а не 100 ₽). Это исключает кассовый разрыв.

# 9. РЕГЛАМЕНТ 152-ФЗ: АНОНИМИЗАЦИЯ

При отзыве согласия на обработку ПДн:
1. Запрещено вызывать `DELETE User` (вызовет ошибку базы данных для защиты истории).
2. Нажмите **`[⚖️ 152-ФЗ Анонимизировать]`**:
   * Email заменяется на `anonymized_[cuid]@deleted.local`.
   * Пароли, сессии и Telegram Chat ID стираются.
   * Финансовые транзакции сохраняются в обезличенном виде на 5 лет (ст. 23 НК РФ).
