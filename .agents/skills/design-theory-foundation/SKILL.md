# Design Theory Foundation — академический фундамент

## When to activate

- Нужна проверка UI на соответствие базовым принципам дизайна
- Пользователь спрашивает про теорию дизайна (композиция, ритм, контраст)
- При audit интерфейса на нарушение принципов CRAP
- Обучающий контекст — нужно объяснить ПОЧЕМУ дизайн-решение работает
- При формулировании дизайн-правил для скиллов

## 7 функций графического дизайна

1. **Стимулирование** — побуждение к действию (CTA, конверсионные элементы)
2. **Информирование** — передача данных (контент, features, спецификации)
3. **Организация** — структурирование информации (навигация, layouts, журналы)
4. **Локализация / Навигация** — пространственная ориентация (wayfinding, меню, breadcrumbs)
5. **Идентификация** — узнавание бренда (логотип, фирменный стиль)
6. **Притягивание внимания** — первая точка контакта (hero, баннеры)
7. **Визуальное удовольствие** — эстетическое удовлетворение (анимации, типографика)

**Правило:** Каждый экран должен выполнять хотя бы одну функцию. Если ни одной — элемент лишний. Если более трёх — когнитивная перегрузка.

## Четыре базовых принципа (CRAP)

### Контраст
Если элементы неодинаковы — сделайте их РАЗНЫМИ. Слабое различие хуже, чем одинаковость.

### Повторение
Каждый визуальный паттерн (border-radius, shadow, font-size) должен повторяться для аналогичных элементов.

### Выравнивание
Не бывает «просто отступ». Каждый отступ — это выравнивание по невидимой линии.

### Приближенность (proximity)
Расстояние между элементами — это информация. Близкие = группа. Далёкие = разные сущности.

## 5 признаков композиции

1. **Повторение целого и его частей** — повторение визуальных токенов создаёт ощущение системы
2. **Соподчинённость** — визуальная иерархия: заголовок → подзаголовок → тело → caption
3. **Соразмерность** — типографическая шкала, spacing scale, единый ритм
4. **Равновесие** — визуальный вес левой и правой частей экрана
5. **Единство** — все четыре признака вместе = композиционное единство

## Три функции цвета

1. **Коммуникативная** — выделение, различение, объединение
2. **Познавательная** — символическое кодирование (зелёный = ОК)
3. **Выразительная** — эмоциональное выражение

## Семиотика: знаки и символы

- **Символы** — абстрактные, без визуальной связи (логотип Nike)
- **Индексы** — стилизация (иконка поиска — лупа)
- **Иконы** — документальное изображение (фото продукта)
- **Правило:** Набор иконок должен быть единообразным — все одного типа

## Step-by-step execution protocol

1. **Identify violations**: Проверить UI на нарушение принципов CRAP
2. **Check 7 functions**: Определить какие функции выполняет каждый экран
3. **Audit composition**: Проверить 5 признаков композиции
4. **Typography check**: Оценить типографическую иерархию и шкалу
5. **Color audit**: Проверить семантику и консистентность цветов
6. **Semiotics check**: Оценить единообразие иконок и знаковой системы
7. **Generate report**: Сформировать отчёт с нарушениями и рекомендациями
8. **Apply fixes**: Предложить конкретные изменения для приведения к принципам

## Scope boundaries

### DOES

- Проверять UI на соответствие академическим принципам дизайна
- Аудитить композицию, типографику, цвет, семиотику
- Объяснять ПОЧЕМУ дизайн-решение работает (теоретическая база)
- Формулировать правила для других скиллов

### DOES NOT

- Заменять профессиональный дизайн-audit с реальным дизайнером
- Гарантировать что теоретически правильный = конверсионно эффективный
- Навязывать конкретные стили (только принципы)
- Игнорировать бизнес-контекст ради «чистой теории»

## Error handling

| Scenario | Response |
|----------|----------|
| Теория противоречит бизнес-требованиям | Приоритет — бизнес, но зафиксировать теоретическое нарушение |
| Принципы конфликтуют друг с другом | Определить приоритет: Контраст > Повторение > Выравнивание > Приближенность |
| Клиент хочет нарушить принцип осознанно | Допустимо, если есть обоснование (авангард, брутализм) |
| Не хватает данных для полной проверки | Сфокусироваться на CRAP, остальные принципы по возможности |
