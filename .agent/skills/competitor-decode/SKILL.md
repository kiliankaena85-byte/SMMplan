# Competitor Decode — Декодирование конкурентов

## When to activate

- Пользователь упоминает сайт конкурента или просит «сделать как у них»
- Проектируется новый раздел и нужен конкурентный контекст
- Команда обсуждает позиционирование относительно конкурентов
- Запущен процесс редизайна и нужен baseline
- Пользователь спрашивает «почему у конкурента это работает»

## ФАЗА 1: DECODE (Декодирование — не просмотр)

Агент НЕ просто смотрит на сайт. Агент задаёт себе структурированные вопросы:

### 1.1 Структурный анализ
- Что является PRIMARY CTA? Где он? Какого размера?
- Какова иерархия контента? Что первое, что второе?
- Как устроена навигация? Сколько уровней?
- Где расположен social proof? В какой форме?

### 1.2 Психологический анализ
- Какой эмоциональный триггер активирует hero? (страх / желание / любопытство / принадлежность)
- Какой bias используется на pricing странице? (anchoring / scarcity / social proof / loss aversion)
- Как снимаются возражения? Где именно на странице?
- Что делает пользователь ПЕРВЫМ делом по намерению конкурента?

### 1.3 Технический анализ
- Есть ли micro-animations? Какова их функция?
- Как устроена типографическая иерархия?
- Какова визуальная плотность? (1-10 шкала)
- Есть ли адаптивные элементы под разные сегменты?

### 1.4 Бизнес-анализ
- На какой сегмент аудитории это направлено?
- Какое позиционирование? (premium / mass / niche)
- Что конкурент считает своим главным УТП?
- Какие боли клиента он адресует?

## ФАЗА 2: ОЦЕНКА (Steal / Adapt / Reject)

Для каждого элемента — решение по матрице:

| Категория | STEAL (взять) | ADAPT (адапт.) | REJECT (откл.) |
|-----------|--------------|----------------|----------------|
| Критерий | Паттерн работает universally | Идея верная, но контекст другой | Противоречит нашей аудитории или стратегии |
| Психология | Психологический принцип доказан | Визуал ≠ наш бренд, но принцип верен | Требует ресурсы которых нет |

## ФАЗА 3: Gap Analysis

Матрица: [Feature] x [Us / Competitor A / Competitor B]
- Где мы лучше → amplify
- Где мы хуже → fix or reframe
- Где никто не делает → opportunity

## Browser Agent Integration

Screenshot Audit через Browser Sub-Agent:
```text
agent.screenshot([
  competitor_homepage,
  competitor_pricing,
  competitor_onboarding_step1,
  competitor_email_signup
])
```

## Step-by-step execution protocol

1. **Screenshot capture**: Запустить Browser Agent, сделать скриншоты ключевых страниц конкурента (hero, pricing, onboarding, checkout)
2. **Structural decode**: Провести структурный анализ (CTA, иерархия, навигация, social proof)
3. **Psychological decode**: Определить эмоциональные триггеры, когнитивные биасы, точки снятия возражений
4. **Technical decode**: Оценить типографику, анимации, визуальную плотность, адаптивность
5. **Business decode**: Идентифицировать целевую аудиторию, позиционирование, УТП, боли
6. **Steal/Adapt/Reject matrix**: Для каждого элемента принять решение с обоснованием
7. **Gap Analysis**: Сравнить с нашим проектом, найти точки превосходства и отставания
8. **Output**: Аннотированный отчёт с рекомендациями и приоритетами

## Scope boundaries

### DOES
- Декодировать дизайн-решения конкурентов с пониманием ПОЧЕМУ они работают
- Оценивать применимость решений к нашему контексту
- Формировать рекомендации: steal / adapt / reject
- Проводить gap analysis между нами и конкурентами
- Использовать Browser Agent для screenshot audit

### DOES NOT
- Копировать визуальные решения напрямую без анализа
- Делать выводы без проверки применимости к нашему ICP
- Заменять A/B тестирование конкурентным анализом
- Гарантировать что решение конкурента сработает для нас
- Анализировать бизнес-модель конкурента (только UX/UI)

## Error handling

| Scenario | Response |
|----------|----------|
| Сайт конкурента недоступен | Использовать кэш из brain/competitors/, сообщить пользователю о timestamp |
| Browser Agent не может сделать screenshot | Предложить ручную загрузку скриншота пользователем |
| Недостаточно данных для Gap Analysis | Запросить у пользователя информацию о своём продукте |
| Конкурент использует A/B тест (разные версии) | Зафиксировать обе версии, отметить как «тестируемый элемент» |
| Пользователь просит «скопировать» | Перенаправить на протокол Decode→Adapt, объяснить риски прямого копирования |
