# ТЕХНИЧЕСКОЕ ЗАДАНИЕ И ПРОМПТЫ ДЛЯ РАЗРАБОТКИ ДОПОЛНИТЕЛЬНЫХ ТЕСТОВЫХ СЬЮТОВ (БЛОКИ 12–17)

> **Назначение**: Полный пакет детализированных промптов для внешних AI-агентов (Cursor, Claude Code, Gemini, Antigravity) на разработку и расширение тестового покрытия платформы SMMplan / SMMflux.

---

## 🏛️ ОБЩИЕ ПРАВИЛА И АРХИТЕКТУРНЫЕ ИНВАРИАНТЫ ДЛЯ ВСЕХ ПРОМПТОВ

Каждый агент, выполняющий разработку тестов, **ОБЯЗАН строго соблюдать следующие инварианты проекта**:

1. **Стек и окружение**: Next.js 16 (Turbopack/Webpack), React 19, TypeScript 5.7+ (strict mode, no `any`), Playwright Test, Prisma 5 (PostgreSQL 15), Redis 7 (BullMQ), Tailwind CSS 4.
2. **Финансовый контур (Trust Boundary)**:
   - Все операции с балансом пользователя (`User.balance`) производятся **ТОЛЬКО** через методы `WalletOps.credit()`, `WalletOps.debit()`, `WalletOps.charge()`, `WalletOps.refund()`.
   - Все денежные суммы — строго в целых числах `BigInt` (в копейках: 100.00 ₽ = `10000n`). Запрещено использовать `Number()` для денег.
   - Каждая транзакция обязана содержать уникальный `idempotencyKey`.
3. **Мульти-тенантность (SMMplan & SMMflux)**:
   - В системе существуют СТРОГО 2 бренда: `smmplan` (`smmplan.pro`) и `flux` (`smmflux.ru`).
   - Запросы к заказам, тикетам, услугам обязаны фильтроваться по `tenantId`. Межсайтовый доступ (IDOR) запрещен.
4. **Шифрование секретов (AES-256-GCM Vault)**:
   - Все API-ключи провайдеров и пароли прокси хранятся в формате `iv:authTag:ciphertext` (`VaultService.encrypt` / `VaultService.decrypt`).
5. **Формат сдачи тестов**:
   - Файлы тестов создаются в папке `e2e/` с именами `12-*.spec.ts`, `13-*.spec.ts` и т.д.
   - Каждый тестовый сьют обязан иметь `beforeAll` (создание тестовых сущностей в БД с уникальными префиксами) и `afterAll` (полная очистка тестовых данных).
