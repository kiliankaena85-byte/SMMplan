# Глубокий аудит модуля каталога SMMplan

**Дата проведения**: 29 июля 2026 г.  
**Область аудита**: Модуль управления каталогом, импорт провайдеров, ценообразование, витрина и интеграция с внешней инфраструктурой SMM-панелей.

---

## 0. Карта модуля

### Схема файлов и архитектурных связей:
```
[ UI Layer ]
┌───────────────────────────────┬────────────────────────────────┐
│ /admin/catalog                │ /admin/providers               │
│ /admin/services (Redirect)    │ /admin/providers/import        │
└───────────────┬───────────────┴───────────────┬────────────────┘
                │                               │
[ Server Actions ]                              │
┌───────────────▼───────────────────────────────▼────────────────┐
│ src/actions/admin/catalog/services.ts                          │
│ src/actions/admin/catalog/sync.ts                              │
│ src/actions/admin/catalog/batch.ts                             │
│ src/actions/admin/catalog/categories.ts                        │
└───────────────┬────────────────────────────────────────────────┘
                │
[ Business Service Layer ]
┌───────────────▼────────────────────────────────────────────────┐
│ src/services/admin/catalog.service.ts                          │
│ src/services/admin/provider.service.ts                       │
│ src/services/admin/category.service.ts                        │
└───────────────┬────────────────────────────────────────────────┘
                │
[ Provider Engine & Shadow Catalog ]
┌───────────────▼────────────────────────────────────────────────┐
│ src/services/providers/provider.service.ts (Redis Cache)      │
│ src/lib/catalog-import/ (normalizers, type-detection)        │
│ src/lib/vault.ts (AES-256-GCM encryption)                      │
└────────────────────────────────────────────────────────────────┘
```

### Flow движения услуги:
`Внешний провайдер (API)` → `Cherry-Pick / Redis-кэш (provider:{id}:catalog)` → `Cherry-Pick Import Wizard (/admin/providers/import)` → `База данных (Service)` → `Quality Gate Validation` → `Витрина клиентского каталога (/services)`.

## 6. Топ-10 проблем модуля по приоритету

1. **[P0]** Отсутствие блокировки `isActive = false` при выявление спайка цен (`priceSpiked`).
2. **[P0]** Перезапись ручных SEO-описаний при автоматическом `syncServicesFromProvider`.
3. **[P0]** SSRF уязвимость при вызове `testConnection` к произвольному `apiUrl`.
4. **[P1]** Отсутствие ограничения размера массива `serviceIds` в Zod-схемах пакетных операций `batch.ts`.
5. **[P1]** Отсутствие авто-определения `targetType` на основе категории при импорте.
6. **[P2]** Монолитный размер `catalog.service.ts` (>1100 строк).
7. **[P2]** Рассинхронизация критерия `Quality Gate` категории между `sitemap.xml` и `noindex` заголовками.
8. **[P2]** Использование цепочек сериализации без СУБД-транзакций при массовом обновлении цен.
9. **[P3]** Дублирование навигационных роутов `/admin/services` и `/admin/catalog`.
10. **[P3]** Логирование неудавшихся синхронизаций без алертинга в Telegram/email администратора.

## 7. Критичные риски

- **SSRF Guard**: Требуется обязательная доработка валидатора URLs перед сетевыми запросами `testConnection`.
- **Финансовые потери**: Необходима немедленная автоматическая деактивация услуг при резком росте закупочных цен от провайдера.
- **Сохранность ручных данных**: Использование флага защиты ручных полей при фоновых синхронизациях.
