## 1. Исполнительное резюме и ландшафт ИИ-инженерии 2026 года

К осени 2026 года сфера автономных агентов разработки программного обеспечения (SWE Agents) перешла в стадию зрелости:
1. **Насыщение SWE-bench Verified:** Флагманские связки моделей (**GPT-6 Astra**, **Claude Opus 5 / Claude 3.7**, **GPT-5.6 Sol**) стабильно показывают результат **90–96%** на эталонном бенчмарке `SWE-bench Verified`. В результате фокус индустрии сместился на **SWE-bench Pro**, **SWE-bench Live** (борьба с контаминацией данных) и специализированный аудит безопасности (**ExploitBench** и **OWASP Top 10 Multi-Turn**).
2. **Разделение на «Агентный ранкодер» (Agent Harness) и «Мыслящее ядро» (Reasoning Model):**
   * Результат зависит не только от модели, но и от интерфейса взаимодействия агента с компьютером (ACI — *Agent-Computer Interface*): умное построение карты репозитория (Repo-Map на Tree-sitter), запуск тестов в песочнице, верификация гипотез и работа с Git.
3. **Триумф открытых CLI-агентов поверх OpenRouter:**
   * Полностью проприетарные облачные среды (Devin) остаются дорогими для непрерывного использования.
   * Связка **«Открытый терминальный агент (Aider / OpenHands / Roo Code) + Фронтирная модель через OpenRouter (GPT-6 Astra / Claude 3.7 / DeepSeek)»** стала де-факто стандартом индустрии по соотношению «качество аудита / приватность кода / контроль расходов».

## 2. Глубокое техническое досье: Коммерческие и Открытые агенты

### 2.1. Коммерческие и проприетарные флагманы

#### 1. OpenAI Codex CLI (`@openai/codex`) + GPT-6 Astra
* **Разработчик:** OpenAI (релиз сентябрь 2026).
* **Архитектура:** Нативный терминальный CLI-агент на Node.js/Rust + фоновый демон с интеграцией в системные вызовы.
* **Базовая модель:** `openai/gpt-6-astra` (1 050 000 токенов контекста, 128k выходных токенов, нативная поддержка Computer/Bash use).
* **Сильные стороны:**
  * Рекордная способность к обнаружению сложных уязвимостей (TOCTOU, гонки многопоточности, обход бизнес-логики). Модель классифицирована OpenAI как критическая для кибербезопасности.
  * Огромное контекстное окно (1.05M) позволяет загрузить всю схему БД, леджер, Server Actions и тесты без потери внимания (Needle-in-a-Haystack > 99.8%).
* **Ограничения:** Встроенные фильтры безопасности (Guardrails) могут блокировать генерацию эксплойтов (модель защитная, defensive-only). Требует настройки `config.toml` для работы через OpenRouter.

#### 2. Claude Code + Claude 3.7 Sonnet / Opus
* **Разработчик:** Anthropic.
* **Архитектура:** Терминальный агент, созданный авторами Claude.
* **Базовая модель:** `claude-3-7-sonnet` / `claude-opus-5`.
* **Сильные стороны:**
  * Выдающееся архитектурное чутье: идеальное соблюдение чистой архитектуры (Clean Architecture), разделения Server/Client компонентов в Next.js App Router.
  * Высокая скорость рефакторинга и минимальный процент регрессий при диффах кода.
* **Ограничения:** Закрытая экосистема агента (заточен строго под модели Anthropic).

#### 3. Cognition Devin
* **Разработчик:** Cognition Labs.
* **Архитектура:** Полностью изолированная облачная виртуальная машина (Debian), встроенный браузер, редактор кода и терминал.
* **Сильные стороны:** Полная автономность: может развернуть сервис, запустить e2e-тесты в браузере, локализовать баг и сделать PR в GitHub без вмешательства человека.
* **Ограничения:** Высокая подписная стоимость (от $500+/мес.), облачный Vendor Lock-in, исходный код проекта передается во внешнее облако Cognition.

### 2.2. Открытые (Open-Source) автономные агенты

#### 1. Aider (Paul Gauthier) — Золотой стандарт терминала
* **Лицензия:** Apache 2.0.
* **Архитектура:** Локальный Python CLI. Индексирует проект в графовую карту через **Tree-Sitter AST (Repo-Map)**.
* **Поддержка моделей:** 100% вендор-независимость. Нативная работа с OpenRouter, OpenAI, Anthropic, Ollama, DeepSeek.
* **Ключевые преимущества:**
  * **Минимальный оверхед токенов:** За счет Repo-Map передает в LLM только сигнатуры релевантных файлов, сокращая расход токенов на 70–85%.
  * **Атомарные Git-коммиты:** Каждое изменение автоматически коммитится с понятным описанием, легко откатить любой шаг (`/undo`).
  * Поддержка двух моделей одновременно: например, слабая/дешевая для Repo-Map и GPT-6 Astra для рассуждений.

#### 2. OpenHands (ранее OpenDevin) — Открытый аналог Devin
* **Лицензия:** MIT.
* **Архитектура:** Python/FastAPI бэкенд + Docker-микропесочница + веб-интерфейс React или Headless CLI.
* **Поддержка моделей:** Любые LLM через LiteLLM и OpenRouter.
* **Ключевые преимущества:**
  * Полная изоляция: агент выполняет `bash`, собирает Docker и прогоняет юнит-тесты внутри защищенного контейнера, не рискуя хостовой ОС.
  * Поддержка мультиагентных ролей (CodeAct Agent, Planner, Browser Agent).
* **Ограничения:** Требует работающего Docker Desktop, выше оверхед по памяти (от 4GB RAM).

#### 3. SWE-agent (Princeton NLP)
* **Лицензия:** MIT.
* **Архитектура:** Академический фреймворк с оптимизированным интерфейсом «Агент-Компьютер» (ACI).
* **Сильные стороны:** Разработан создателями SWE-bench. Специализируется на поиске файлов по регуляркам, чтении с ограничением контекста и генерации точных патчей.
* **Ограничения:** Менее интерактивен для повседневной разработки; оптимизирован под пакетные бенчмарки и авто-фиксы issue.

#### 4. Goose (Block / Square)
* **Лицензия:** Apache 2.0.
* **Архитектура:** Нативный локальный агент на Rust с интеграцией протокола **MCP (Model Context Protocol)**.
* **Сильные стороны:** Работает прямо на машине разработчика, расширяется любыми MCP-серверами (БД, терминал, браузер, документация).
* **Поддержка моделей:** Любые OpenAI-совместимые API, включая OpenRouter.

#### 5. Roo Code / Cline (VS Code Extension)
* **Лицензия:** Apache 2.0.
* **Архитектура:** Расширение для VS Code / Cursor / VSCodium.
* **Сильные стороны:**
  * Нативная интеграция с **OpenRouter**: удобный ввод API-ключа, переключение моделей на лету в GUI, стриминг стоимости каждого запроса в реальном времени.
  * Режимы работы (Architect, Code, Ask, Custom Rules) с поддержкой кастомных системных промптов (можно напрямую скормить `AGENTS.md`).
  * Пошаговое подтверждение каждого изменения и каждой команды терминала (Human-in-the-Loop).

#### 6. AutoCodeRover (National University of Singapore)
* **Лицензия:** Apache 2.0.
* **Архитектура:** AST-ориентированный агент локализации дефектов.
* **Сильные стороны:** Вместо чтения сотен строк кода запрашивает конкретные классы, методы и AST-узлы. Очень эффективен для поиска скрытых логических багов с минимальным расходом токенов.

#### 7. Plandex
* **Лицензия:** AGPL-3.0.
* **Архитектура:** Терминальный агент на Go, оптимизированный под крупные архитектурные задачи.
* **Сильные стороны:** Строит долгосрочные деревья планов, выполняет изменения в изолированной ветке (sandbox branch) и показывает интерактивный diff перед применением.

## 4. Экономический расчет: Тотальный аудит кодовой базы OmniSMM

### 4.1. Профиль проекта OmniSMM 1.0
* **Объем кодовой базы:** ~1 500 000 токенов (TypeScript, React 19, Next.js 16, Prisma, Server Actions, Workers, Тесты).
* **Критические зоны проверки:**
  1. Финансовый модуль (`WalletOps`, Ledger-First инвариант, ExactMath в копейках).
  2. Защита от состояний гонки (TOCTOU) при списании баланса и чекауте.
  3. Изоляция тенантов (`smmplan` vs `smmflux`, барьер ст. 54.1 НК РФ).
  4. OWASP Top 10:2026 (Timing-Safe вебхуки, BOLA/IDOR в API, санитизация промокодов).

> Использование открытого агента **Aider** (который строит AST-карту репозитория и передает только зависимые файлы и критические контексты) снижает стоимость глубокого аудита Astra до **$3.50–$5.00** за полный цикл, полностью устраняя «шумовой» контекст!

## 5. Дорожная карта и конфигурация для OmniSMM

### Вариант 1 (РЕКОМЕНДУЕМЫЙ): Aider + GPT-6 Astra через OpenRouter
Идеально для детальной проверки репозитория из терминала с полным сохранением Git-истории.

#### Шаг 1. Установка Aider
```powershell
pip install aider-chat
```

#### Шаг 2. Запуск аудита с ключом OpenRouter
В корне `e:\SMM`:
```powershell
# Экспорт ключа из существующего .env проекта
$env:OPENROUTER_API_KEY = (Get-Content .env | Select-String "^OPENROUTER_API_KEY=").Line.Split("=",2)[1].Trim()

# Запуск в режиме только для чтения (Architect / Review mode)
aider --model openrouter/openai/gpt-6-astra `
      --read AGENTS.md `
      --read prisma/schema.prisma `
      --read src/services/wallet.service.ts `
      --read src/utils/exact-math.ts
```

#### Команда для тотальной проверки внутри Aider:
> *"Проведи тотальный аудит безопасности: найди любые возможности Transaction Escape в WalletOps, проверь соблюдение Ledger-First, протестируй санитизацию промокодов на ReDoS и проверь защиту от TOCTOU race conditions при списании баланса."*

---

### Вариант 2: Roo Code / Cline в VS Code (Визуальный интерактивный аудит)
1. Установите расширение **Roo Code** (или **Cline**) в VS Code.
2. В настройках API Provider выберите **OpenRouter**.
3. В поле API Key вставьте ключ из `.env`.
4. В поле Model ID введите `openai/gpt-6-astra`.
5. Включите режим **Code** или **Architect** и передайте файл `@AGENTS.md` в контекст диалога.

---

### Вариант 3: OpenAI Codex CLI (`@openai/codex`)
Для тех, кто предпочитает официальный агентный тулинг OpenAI:
1. `npm install -g @openai/codex`
2. Создайте файл `C:\Users\ZVER\.codex\config.toml`:
```toml
model = "openai/gpt-6-astra"
model_provider = "openrouter"

[model_providers.openrouter]
name = "OpenRouter"
base_url = "https://openrouter.ai/api/v1"
env_key = "OPENROUTER_API_KEY"
wire_format = "openai"
```
3. Запуск: `codex "Выполни проверку финансовых инвариантов проекта"`.

## 6. Итоговый вердикт

1. **Самая мощная модель для тотального аудита безопасности на сегодня:** **OpenAI GPT-6 Astra** (`openai/gpt-6-astra` на OpenRouter). Ее превосходство в логическом выводе, ExploitBench и окне в 1.05M токенов не имеет равных среди других моделей осени 2026 года.
2. **Лучший агентный инструмент для запуска:**
   * Если нужен быстрый терминальный аудит без раздувания затрат — **Aider**.
   * Если нужен визуальный интерфейс в редакторе с подтверждением каждого диффа — **Roo Code**.
   * Если нужен глубокий запуск тестов и bash в изолированной песочнице — **OpenHands** в Docker.
