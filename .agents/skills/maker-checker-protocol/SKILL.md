# Maker-Checker Protocol (Кодер + QA-Ревьюер)

Этот скилл регламентирует процедуру перекрестной проверки кода с использованием независимого субагента-ревьюера без прав на запись (Checker).

## 1. Конфигурация Checker-субагента
Каждый раз, когда планируются изменения в ключевой логике, фронтенде или API проекта SMMplan, Maker (основной агент) обязан объявить независимого субагента-цензора.

Используйте инструмент `define_subagent` со следующими параметрами:

```json
{
  "name": "qa_reviewer",
  "description": "Независимый QA-аудитор кода SMMplan. Проверяет изменения на соответствие архитектурному контракту, отсутствие костылей и галлюцинаций.",
  "system_prompt": "Ты — строгий QA-ревьюер проекта SMMplan (Checker). Твоя цель — провести беспристрастный аудит предложенного Maker-агентом кода. Проверь его по следующим пунктам:\n1. Соответствие AGENTS.md (Next.js 16, React 19, Tailwind CSS 4, HeroUI v3).\n2. Отсутствие inline-цветов (text-white, bg-black, bg-blue-500) — должны использоваться только семантические токены (text-foreground, bg-background, text-primary).\n3. Отсутствие заглушек (// TODO, FIXME) и нетипизированного кода (any без объяснения, ts-ignore).\n4. Отсутствие галлюцинаций API (вызовы несуществующих функций Next.js или React).\n5. Безопасность (Trust Boundary, проверка цен на сервере, защита от IDOR).\n\nНапиши развернутый отчет с указанием строк кода. Выстави оценку: PASS или FAIL.\nТебе ЗАПРЕЩЕНО самостоятельно изменять файлы проекта (у тебя отключены инструменты записи).",
  "enable_write_tools": false,
  "enable_mcp_tools": true,
  "enable_subagent_tools": false
}
```

## 2. Процедура аудита (Инструкция для Maker)
1. Перед внесением изменений инициализируй субагента с помощью `define_subagent` (если он еще не инициализирован в рамках текущей сессии).
2. Запусти субагента с помощью `invoke_subagent` с `TypeName: "qa_reviewer"`.
3. После того как ты изменил файлы и проверил их работоспособность локально (Vitest, tsc), отправь запрос субагенту через `send_message`:
   ```text
   Пожалуйста, проведи ревью изменений. Вот список файлов и диффы:
   [Вставь diff изменений или укажи пути к измененным файлам]
   ```
4. Получи сообщение-ответ от `qa_reviewer`.
5. Если вердикт `FAIL` — исправь замечания и повтори шаг 3.
6. Если вердикт `PASS` — ты можешь завершать выполнение задачи.
