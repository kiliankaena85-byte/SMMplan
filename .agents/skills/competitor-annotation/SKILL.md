# Competitor Annotation — 5 слоёв анализа

## When to activate

- Нужно проанализировать конкретный элемент дизайна конкурента (не весь сайт)
- Пользователь спрашивает «почему этот элемент работает»
- Создаётся библиотека паттернов с оценками
- Проводится деконструкция hero, pricing, onboarding и т.д.
- Нужны аннотированные карточки для презентации клиенту

## ПРОТОКОЛ АННОТАЦИИ — 5 слоёв анализа

Для каждого элемента конкурента агент создаёт карточку:

### КАРТОЧКА ЭЛЕМЕНТА:

**ЭЛЕМЕНТ:** [название, например "Hero Section"]
**СКРИНШОТ:** [ссылка или base64]

#### СЛОЙ 1 — ЧТО это?
"Fullscreen video hero с текстом поверх, один CTA по центру, без навигации"

#### СЛОЙ 2 — ЗАЧЕМ это работает? (психология)
"Устраняет cognitive overload — один выбор. Видео создаёт эффект присутствия. Центральный CTA использует F-pattern scanning."

#### СЛОЙ 3 — ДЛЯ КОГО это работает?
"Для аудитории с high visual literacy, доверяющей premium брендам. НЕ работает для B2B с длинным циклом сделки."

#### СЛОЙ 4 — РИСКИ этого подхода
"Долгая загрузка видео → bounce на мобайле. Нет немедленного value proposition в тексте. Зависит от качества видеопроизводства."

#### СЛОЙ 5 — АДАПТАЦИЯ для нашего проекта
- ЕСЛИ [наша аудитория схожа] → применить напрямую
- ЕСЛИ [наша аудитория отличается] → адаптировать так: ...
- ЕСЛИ [наш стек не поддерживает] → альтернатива: ...
- ЕСЛИ [противоречит нашему позиционированию] → отклонить

## Step-by-step execution protocol

1. **Identify element**: Определить конкретный UI-элемент для анализа (hero, CTA, pricing card, navigation и т.д.)
2. **Screenshot capture**: Сделать скриншот элемента через Browser Agent
3. **Layer 1 — Describe**: Описать что это визуально (layout, components, content)
4. **Layer 2 — Psychology**: Определить психологический механизм (bias, emotion, cognitive principle)
5. **Layer 3 — Audience**: Оценить для какой аудитории это работает, для какой — нет
6. **Layer 4 — Risks**: Перечислить риски подхода (performance, accessibility, brand fit)
7. **Layer 5 — Adaptation**: Принять решение о применимости к нашему проекту
8. **Card output**: Сформировать аннотированную карточку в стандартном формате

## Scope boundaries

### DOES
- Создавать 5-слойные аннотированные карточки для любого UI-элемента
- Оценивать психологические механизмы дизайна
- Формировать рекомендации по адаптации
- Работать с Browser Agent для автоматического скриншотинга

### DOES NOT
- Анализировать целые сайты целиком (используйте competitor-decode)
- Заменять юзабилити-тестирование
- Гарантировать что адаптация сработает (нужен A/B тест)
- Оценивать бизнес-метрики конкурента

## Error handling

| Scenario | Response |
|----------|----------|
| Элемент не виден на скриншоте | Запросить у пользователя уточнение, какой именно элемент анализировать |
| Недостаточно контекста для Слоя 3 | Запросить ICP пользователя из client-dna skill |
| Неопределённость в Слое 5 | Предложить два варианта адаптации с обоснованием |
| Несколько элементов на одном скриншоте | Разбить на отдельные карточки |
