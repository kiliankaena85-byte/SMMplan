# Triage — быстрая оценка задачи и выбор уровня

Triage — это **Фаза 1** скилла. Её цель: за один проход (без раундов) понять, нужен ли вообще круглый стол, и если да — какой уровень глубины. Triage делает один агент за ~30-60 секунд, без вовлечения специалистов.

## Принцип

Большинство задач в реальной разработке — **тривиальные или простые**. Для них круглый стол = потеря времени. Triage отличает их от действительно сложных задач и активирует скилл только когда он нужен.

## Два возможных исхода Triage

### Исход A: «Пропустить» (Level 0)
Задача слишком простая для круглого стола. Агент приступает к имплементации без скилла.

**Критерии:**
- 1 система, типовая фича
- <200 строк ожидаемого кода
- 1 файл изменений
- Нет новых API контрактов
- Нет миграций БД
- Нет рисков регрессий
- Нет security/perf требований

**Действие:** Сообщить пользователю: «Задача простая, делаю без круглого стола. Если хочешь план — скажи.»

### Исход B: «Запустить скилл» (Level 1/2/3)
Задача требует планирования. Triage определяет уровень и состав.

## Четыре уровня глубины

| Level | Название | Состав | Когда | Время | Вывод |
|-------|----------|--------|-------|-------|-------|
| 0 | Skip | — | Тривиальная, 1 система, <200 строк | 0 (без скилла) | Код сразу |
| 1 | Lite | Triage + Архитектор + QA (один агент) | 2 системы, типовая фича | 1-2 мин | Чат-рецепт |
| 2 | Standard | Triage + 4-5 ролей через subagents | 3+ системы, новые требования | 3-5 мин | Чат-рецепт + compact-план в файл |
| 3 | Deep | Triage + 6-7 ролей через subagents | Архитектурные изменения, миграции, платежи | 5-10 мин | Чат-рецепт + полный план (17 разделов) |

## Матрица принятия решения

Пройди по чек-листу снизу вверх. Первое совпадение определяет уровень.

### Level 3 (Deep) — если ЛЮБОЕ из:
- ✅ Архитектурные изменения (новая схема БД, новый сервис)
- ✅ Миграция данных с downtime-риском
- ✅ Платёжный или аутентификационный flow
- ✅ Затронуты PII, GDPR, PCI compliance
- ✅ Breaking changes в публичном API
- ✅ Ожидается >1000 строк кода или >5 файлов изменений
- ✅ Множественные интеграции с внешними сервисами
- ✅ Пользователь явно попросил «глубокий анализ»

### Level 2 (Standard) — если ЛЮБОЕ из:
- ✅ 3+ систем затронуто (frontend + backend + БД, или несколько микросервисов)
- ✅ Новые требования с неоднозначностями
- ✅ Edge-cases, которые нужно проработать
- ✅ Публичная страница (SEO-значимая)
- ✅ Ожидается 200-1000 строк кода, 2-5 файлов
- ✅ Затронут существующий функционал с риском регрессий
- ✅ Нужны UI/UX решения (не просто косметика)

### Level 1 (Lite) — если ЛЮБОЕ из:
- ✅ 2 системы затронуты (например, frontend + backend)
- ✅ Новая endpoint без сложной бизнес-логики
- ✅ Типовая фича с известным паттерном
- ✅ Ожидается 50-200 строк кода
- ✅ Небольшой риск регрессий

### Level 0 (Skip) — если ВСЕ из:
- ✅ 1 система
- ✅ Типовая правка (fix, refactor, small feature)
- ✅ <50 строк кода, 1 файл
- ✅ Нет миграций, нет новых API
- ✅ Нет рисков регрессий
- ✅ Нет security/perf аспектов

## Что Triage выводит

После анализа Triage объявляет решение в формате:

```
## 🔍 Triage: [Level N — Название]

**Задача:** [1 предложение, переформулировка]

**Признаки:**
- [признак 1 — например, "3 системы: frontend, backend, БД"]
- [признак 2 — например, "новые требования с edge-cases"]
- [признак 3 — например, "риск регрессий в существующем flow"]

**Решение:** [Level N, потому что ...]

**Состав:** [роли через запятую]
**Формат вывода:** [чат-рецепт / чат-рецепт + файл]
**Ожидаемое время:** [N мин]

**План действий:**
1. [Если Level 0: приступаю к коду]
2. [Если Level 1+: запускаю Архитектор → ...]
```

## Принципы Triage

### Лучше недооценить, чем переоценить
Если сомневаешься между Level 1 и Level 2 — выбирай Level 1. Если между 2 и 3 — выбирай 2. Избыточный круглый стол для простой задачи раздражает больше, чем недостаточный для сложной.

### Учитывай контекст пользователя
- Если пользователь торопится («быстро сделай X») — снижай уровень
- Если пользователь явно хочет продумать («оцени комплексно») — повышай
- Если в истории уже были вопросы по этой задаче — повышай (значит, не простая)

### Уважай время
Triage сам по себе должен занимать 30-60 секунд. Если дольше — ты его усложняешь. Это быстрый анализ, не глубокий.

### Объясняй решение
Пользователь должен понимать, ПОЧЕМУ выбран этот уровень. Если он не согласен — пусть скажет «давай глубже» или «проще». Прозрачность важнее догматичности.

### Проверяй явные сигналы
- «спланируй через круглый стол» → минимум Level 2
- «глубокий анализ» → Level 3
- «быстро» / «просто сделай» → Level 0 или 1
- «оцени риски» → минимум Level 2 (нужен Security)
- «threat model» → Level 3 (Security обязательно)

## Антипаттерны

❌ **Не запускай скилл для каждой задачи** — большинство задач тривиальные, скилл раздражает
❌ **Не пропускай Triage** — это главный гейтинг, без него скилл активируется слишком часто
❌ **Не усложняй Triage** — это быстрый анализ, не раунд специалистов
❌ **Не меняй уровень после Triage без причины** — если выбрал Level 2, не перескакивай на 3 в середине. Если вскрылась новая сложность — спроси пользователя
❌ **Не прячь решение** — пользователь должен видеть, какой уровень и почему

## Примеры

### Пример 1: «Добавь поле bio в профиль пользователя»
- 1 система (backend)
- Типовая правка
- ~30 строк, 2 файла (model + migration)
- Нет рисков

**Triage:** Level 0 — Skip. «Делаю без круглого стола. Если хочешь план — скажи.»

### Пример 2: «Добавь OAuth через Google»
- 3 системы: frontend, backend, БД
- Аутентификация → security critical
- Новые edge-cases (link account, token refresh)

**Triage:** Level 3 — Deep. Состав: Архитектор, Data Engineer, Security, UI/UX, QA. Ожидаемое время: 5-10 мин.

### Пример 3: «Редизайн главной страницы»
- 2 системы: frontend, контент
- Публичная страница → SEO
- LCP критичен

**Triage:** Level 2 — Standard. Состав: Архитектор, UI/UX, Frontend Performance, SEO, QA. Ожидаемое время: 3-5 мин.

### Пример 4: «Реши issue #42 — падает тест на CI»
- 1 система
- Bug fix
- ~10-50 строк

**Triage:** Level 0 — Skip. «Делаю без плана, это багфикс.»

### Пример 5: «Мигрируем с PostgreSQL на MySQL»
- Миграция данных с downtime-риском
- Multiple систем: БД, ORM, queries

**Triage:** Level 3 — Deep. Состав: Data Engineer, Архитектор, DevOps, Performance, QA. Ожидаемое время: 8-10 мин.

## Что делает агент после Triage

- **Level 0:** Сообщает решение, приступает к коду
- **Level 1:** Запускает Архитектор (один проход), потом QA, потом синтез → чат-рецепт
- **Level 2:** Читает `references/subagent-orchestration.md`, запускает 4-5 subagents параллельно, потом синтез → чат-рецепт + compact-план в файл
- **Level 3:** Читает `references/subagent-orchestration.md`, запускает 6-7 subagents параллельно, потом синтез → чат-рецепт + полный план (17 разделов) в файл

В любом случае (Level 1+) — переходит к Шагу 1 (Открытие модератора) с уже определённым составом.
