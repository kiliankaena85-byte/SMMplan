## Детальный разбор по областям аудита

### R1. User Flow (Блок 2.1) — MEDIUM расхождение

**Найдено в коде (`useCheckoutOrchestrator.ts`):**
1. Клиент заполняет форму: ссылка, услуга, количество, email (обязательно).
2. При сабмите — валидация ссылки через `getLinkValidator`.
3. Открывается **`PaymentGatewaySelectionModal`** — клиент выбирает шлюз.
4. Заказ создаётся через `checkoutAction` со статусом `AWAITING_PAYMENT`.
5. Редирект на `paymentUrl` платёжного шлюза.
6. По webhook — статус → `PENDING`, создание аккаунта / привязка к существующему.

**Что в мануале:** шаг «выбор шлюза» отсутствует. Создание аккаунта описано как «после оплаты», но email вводится ДО.

### R2. Статусы заказов (Блок 2.4) — HIGH расхождение

**Реальный enum из `prisma/schema.prisma`:**
```
AWAITING_PAYMENT  — ожидает оплату (до webhook)
PENDING           — оплачен, ждёт воркера
PENDING_CHECK     — на проверке (промежуточный)
PROVISIONING      — отправляется провайдеру
IN_PROGRESS       — провайдер выполняет
COMPLETED         — завершён
PARTIAL           — частично выполнен
CANCELED          — отменён
ERROR             — ошибка
CANCELING         — в процессе отмены
```

**Что в мануале:**
- `PENDING` — ✅ (есть)

- `IN_PROGRESS` — ✅
- `COMPLETED` — ✅
- `PARTIAL` — ✅
- `CANCELED` — ✅
- `AWAITING_PAYMENT` — ❌ отсутствует
- `PENDING_CHECK` — ❌ отсутствует
- `PROVISIONING` — ❌ отсутствует

### R3. Платёжные шлюзы (Блок 2.3) — HIGH расхождение

**Реальные шлюзы (из `PaymentGatewaySelectionModal.tsx` и `src/app/api/webhooks/`):**

### R4. Роли персонала (Блоки 4.3–4.6, 9.1) — MEDIUM расхождение

**Реальная RBAC из кода:**

| Системная роль | Доступ | Особенности |
|---|---|---|
| `OWNER` | Всё | Bypass всех проверок RBAC. Видит закупочные цены. |
| `ADMIN` | Всё кроме Owner-actions | Полный доступ к панели |
| `MANAGER` | По `StaffRole` + `canView`/`canEdit` | Дневной лимит компенсаций (`supportLimitCents`) |
| `SUPPORT` | По `StaffRole` + `canView`/`canEdit` | Не видит закупочные цены (`canSeeRates = false`). Лимит компенсаций. Не может вызвать `manual bind` в тикетах. |

Дополнительно: кастомные `StaffRole` (создаются OWNER-ом) с гранулярными правами на разделы: `orders`, `finance`, `catalog`, `settings`, `clients`, `tickets`, `refills`, `providers`, `pages`, `dashboard`, `quarantine`, `features`, `queues`, `marketing`.

**Что в мануале:** система RBAC не описана. Упоминается только «доступ в админ-панель» и «начисление компенсаций».
