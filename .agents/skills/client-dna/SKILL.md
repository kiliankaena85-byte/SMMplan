# Client-DNA — «Бизнес-ДНК» заказчика

## When to activate

- Начинается работа с новым клиентом / проектом
- Пользователь просит спроектировать UI без указания бизнес-контекста
- Нужно уточнить ICP, tone of voice, позиционирование
- Перед генерацией любого UI для клиентского проекта
- В brain/ нет записи client-dna для текущего проекта

## Обязательные вопросы перед проектированием

Агент ДОЛЖЕН прояснить эти параметры ДО генерации любого UI:

### 1. Кто покупает? (ICP — Ideal Customer Profile)
- Возраст, опыт, tech-savviness
- Где принимает решение: мобайл/десктоп/офис/дорога
- Что читает, кому доверяет, чего боится
- Пример: "CFO 45 лет, iPad на совещаниях, доверяет Forbes"
  → консервативный layout, данные > визуалы, serif typography

### 2. Какова единственная главная цель страницы?
- Не «рассказать о продукте»
- А конкретно: «получить email», «записать на демо», «купить план»
- Один экран = одна цель = один primary CTA

### 3. Что мешает конверсии прямо сейчас?
- Возражения: цена, доверие, сложность, время
- Каждое возражение = блок на странице, который его снимает

### 4. Тон голоса бренда
- Spectrum: Technical ↔ Friendly
- Spectrum: Formal ↔ Casual
- Spectrum: Bold ↔ Subtle
- Пример: «как умный друг, а не как корпорация»

### 5. Конкуренты и позиционирование
- Чем мы НЕ являемся (важнее, чем чем являемся)
- Что конкуренты делают хорошо (не повторять, а превзойти)
- Что они делают плохо (наша точка отличия)

## Step-by-step execution protocol

1. **Check brain/**: Проверить, есть ли уже client-dna запись для проекта
2. **Ask ICP**: Задать вопросы о целевой аудитории (кто, где, как решает)
3. **Define page goal**: Уточнить единственную цель текущей страницы
4. **Identify objections**: Выявить 3 главных возражения к конверсии
5. **Map tone of voice**: Определить позицию на спектрах Technical↔Friendly, Formal↔Casual, Bold↔Subtle
6. **Competitive context**: Понять позиционирование относительно конкурентов
7. **Save to brain/**: Записать client-dna в `.gemini/antigravity/brain/client-dna/`
8. **Proceed to design**: Только после заполнения всех 5 пунктов — приступать к UI

## Scope boundaries

### DOES
- Извлекать бизнес-контекст клиента ДО генерации UI
- Формировать ICP с конкретными параметрами
- Определять tone of voice на спектрах
- Сохранять client-dna в персистентную память (brain/)
- Связывать каждое дизайн-решение с бизнес-контекстом

### DOES NOT
- Генерировать UI без заполненного client-dna
- Подменять бизнес-контекст генерическими предположениями
- Игнорировать ответы клиента если они «не красивые»
- Навязывать стандартные ICP (каждый клиент уникален)

## Error handling

| Scenario | Response |
|----------|----------|
| Клиент не может описать ICP | Предложить 3 типичных профиля из индустрии на выбор |
| Несколько целевых аудиторий | Попросить приоритизировать, выбрать одну primary для текущей страницы |
| Клиент говорит «для всех» | Объяснить риск, предложить самый платёжеспособный сегмент как primary |
| Tone of voice не определён | Показать 3 примера из конкурентов с разными тонами, попросить выбрать |
