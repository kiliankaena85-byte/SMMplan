# JTBD Design — «Jobs To Be Done» для каждого элемента UI

## When to activate

- Проектируются CTA, заголовки, pricing cards
- Нужна формулировка текстов кнопок и заголовков
- Пользователь спрашивает «какой текст написать на кнопке»
- Каждый элемент на странице должен оправдать своё существование
- При audit страницы на предмет лишних элементов

## Фреймворк JTBD для каждого элемента UI

Каждый элемент должен быть «нанят» для выполнения работы:

### КНОПКА: нанята для → снижения страха перед действием
- Текст кнопки = результат, не действие
- «Начать бесплатно» > «Зарегистрироваться»
- «Получить аудит» > «Отправить форму»
- «Попробовать 14 дней» > «Купить»

### ЗАГОЛОВОК HERO: нанят для → моментального ответа «это для меня»
- Структура: [Кто] + [Результат] + [Без боли]
- «Маркетинговые команды закрывают на 40% больше сделок — без ручной отчётности»

### PRICING PAGE: нанята для → снятия страха перед деньгами
- Показывай value, а не features
- «Экономия 12 часов/неделю» > «Автоматизация отчётов»
- Popular badge на среднем плане (anchoring)

### ФОРМА: нанята для → минимизации трения
- Каждое поле = обоснование зачем оно нужно
- Прогресс-индикатор для форм > 3 шагов
- Inline validation, не после submit

## Правило: нет работы = нет элемента

Если элемент не может сформулировать свою «job» — он лишний. Каждый пиксель должен иметь purpose.

## Step-by-step execution protocol

1. **List all elements**: Перечислить все UI-элементы на странице
2. **Define job for each**: Для каждого — сформулировать «нанят для...»
3. **Check coverage**: Убедиться что все возражения пользователя покрыты
4. **Remove unemployed**: Удалить элементы без чёткой «job»
5. **Optimize copy**: Переписать тексты с точки зрения результата, не действия
6. **Validate with user**: Проверить что каждый элемент отвечает на вопрос пользователя
7. **Prioritize**: Расположить элементы по важности их «job»
8. **Measure**: Определить метрику для каждого элемента

## Scope boundaries

### DOES
- Формулировать «job» для каждого UI-элемента
- Оптимизировать CTA тексты (результат > действие)
- Аудитить страницы на наличие лишних элементов
- Связывать элементы с возражениями пользователя

### DOES NOT
- Заменять user research ( JTBD = гипотеза, не факт)
- Проектировать весь UI (только семантика элементов)
- Гарантировать что CTA-текст сработает (нужен тест)
- Определять визуальный дизайн элементов

## Error handling

| Scenario | Response |
|----------|----------|
| Элемент «красивый, но без job» | Предложить убрать или перепрофилировать |
| Несколько элементов с одинаковой job | Объединить в один, убрать дублирование |
| Клиент хочет «больше элементов» | Объяснить что каждый элемент без job = когнитивный шум |
| CTA-текст не формулируется | Использовать формулу: [Результат] + [Без боли] |
