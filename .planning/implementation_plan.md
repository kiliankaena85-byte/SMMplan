# 🏛️ Архитектурный план: Революция техподдержки Smmplan (B2C & B2B — Этап 2)

Этот документ описывает техническое проектирование и план внедрения продвинутых B2B и B2C функций в службу поддержки **Smmplan** для превращения её в лучшую на рынке реселлинга. 

Мы реализуем:
1. **B2B Bulk Order Parser & Attached Grid**: автоматическое извлечение ID заказов из текста тикета, их вывод в компактную сетку и массовые операции (Bulk Refill/Refund) в один клик прямо из чата.
2. **Conversational AI-First Triage (Gemini 3.5)**: автодиагностика заказов (Remains, ETA, логи провайдера) и мгновенный ответ первой линии.
3. **Умные шаблоны с автозаполнением переменных** (`{client_name}`, `{order_id}`, `{refund_amount}`).
4. **B2B Support API & Webhooks**: шлюз для интеграции техподдержки в сторонние CRM реселлеров.

---

## User Review Required

> [!IMPORTANT]
> **Ключевые архитектурные решения**:
> 1. **Баланс транзакций (Cents Only)**: Все массовые возвраты средств B2B-клиентам будут выполняться строго в рамках единой безопасной Prisma-транзакции с обновлением баланса пользователя в целых копейках (`cents`) и записью записей в финансовый журнал `LedgerEntry`.
> 2. **Human-in-the-Loop эскалация**: Для розничных B2C пользователей при отправке тикета срабатывает ИИ-автоответчик с детальным разбором заказа, а под сообщением выводится кнопка **«Позвать человека»**, переводящая тикет в очередь живых операторов.
> 3. **Вектор оптимизации (Redis Shadow Catalog)**:AI-диагностика использует данные кэша провайдеров и ETA из Redis во избежание таймаутов и Rate Limit блокировок внешних API.

## Архитектурный стык (5 Векторов Надежности)

### 1. 🛡️ Архитектурный стык (Server/Client границы)
*   Интерактивная таблица прикрепленных заказов (`AttachedOrdersGrid`) реализуется как клиентский компонент React 19 с оптимизированными ререндерами (`useTransition`, `React.memo`), минимизируя нагрузку при выборе 50+ чекбоксов.
*   Действия отмены, перезапуска и возврата выносятся в защищенные Server Actions с обязательными валидациями ролей (`requireAdmin`).

### 2. 🕳️ Вектор Хаоса и Пустоты (Cold Start / Empty State)
*   **Синдром пустой БД**: При отсутствии заказов в тикете Regex-парсер безопасно возвращает пустой массив, а таблица `AttachedOrdersGrid` полностью скрывается, не загромождая UI.
*   **Сбой Webhook доставки**: При недоступности сервера реселлера BullMQ-воркер отлавливает ошибку и запускает Retry Backoff до 5 раз.

### 3. 🎨 Visual & UX Density Vector (Warm Ivory)
*   Таблица прикрепленных заказов оформляется по стандартам Vercel/Stripe: чередующийся мягкий фон (`bg-warm-zinc/30` и `bg-warm-card`), отсутствие разделительных `1px lines` для исключения усталости глаз оператора.
*   Плавные CSS-микроанимации при наведении на заказы и переключении чекбоксов (`transition-all duration-200`).

### 4. ♿ Доступность (WCAG 2.2 AA)
*   Все чекбоксы и кнопки пакетных действий в сетке заказов имеют увеличенную интерактивную зону клика (touch targets >= 44px).
*   Контрастность статусных маркеров (зеленый для `COMPLETED`, синий для `IN_PROGRESS`) строго соответствует соотношению не менее 4.5:1.

### 5. 🛡️ Security & Trust Vector
*   **Trust Boundary**: Суммы возвратов за недовыполненные остатки (Remains) рассчитываются строго на сервере по формуле в копейках. Клиентский интерфейс передает только ID заказов, исключая подмену цен.
*   **Prompt Injection Protection**: Входящие сообщения пользователей перед передачей в Gemini 3.5 проходят санитарную фильтрацию и форматируются как структурированные блоки `contents`, исключая системный взлом промпта.

| :--- | :--- | :--- | :--- |
| **Deadlock при массовом B2B возврате 50+ заказов** | 2 (Низкая) × 4 (Высокое) | **8 (Средний)** | Массовый возврат выполняется через последовательный пересчет в копейках с последующим единичным обновлением баланса пользователя (`User.update`) и пакетной записью `LedgerEntry.createMany`, что минимизирует время удержания блокировки строк БД. |
| **Prompt Injection в тикете B2B-клиента с целью сброса инструкций AI** | 3 (Средняя) × 3 (Среднее) | **9 (Средний)** | Входящий текст пользователя полностью изолируется внутри JSON-структуры Gemini API (`contents`), а системные правила передаются исключительно в `system_instruction`. Модель физически не может интерпретировать текст пользователя как команду верхнего уровня. |
| **Удаленный сервер реселлера лежит при отправке Webhook** | 4 (Высокая) × 2 (Низкое) | **8 (Средний)** | Отправка вебхуков делегируется в BullMQ. При ошибках соединения (5xx, Timeout) воркер автоматически перезапускает попытку с экспоненциальной задержкой (Retry Backoff), сохраняя целостность синхронизации. |
