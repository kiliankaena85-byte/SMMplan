# SPEC-2026-09-22: Разделение Промокодов и Партнерской программы (Admin)

## 1. Описание проблемы
В текущей реализации панели администратора раздел "Маркетинг & Промо" (`/admin/marketing`) содержит два внутренних клиентских таба: "Промокоды" и "Партнерская программа" (компонент `MarketingTabs`). Использование вложенных табов (AdminTabbedHeader + MarketingTabs) нарушает UX и усложняет прямую маршрутизацию на конкретный раздел.

## 2. Цели
1. Разделить вкладки "Промокоды" и "Партнерская программа" на два независимых роута в рамках `FINANCE_TABS` (домен `finance`).
2. Удалить вложенный компонент `MarketingTabs`.
3. Сохранить полную функциональность обеих страниц.
4. Выполнить изменения по стандарту Light-SDD (Tier 2).

## 3. Технические изменения

### 3.1. Роутинг и Навигация (`navigation-data.ts`)
- Добавить новый роут `'/admin/promocodes': '/admin/finance'` в `SIDEBAR_DOMAIN_ALIASES`.
- В массиве `FINANCE_TABS` заменить элемент `Маркетинг & Промо` на два отдельных элемента:
  - `{ label: 'Партнерская программа', href: '/admin/marketing' }`
  - `{ label: 'Промокоды', href: '/admin/promocodes' }`
- Разделить `ONBOARDING_CONFIGS` для `marketing` и `promocodes` на две независимые конфигурации, релевантные содержимому страниц.

### 3.2. Страница Партнерской программы (`/admin/marketing/page.tsx`)
- Оставить только загрузку реферальных метрик (`getReferralStats`, `listTopReferrers`, `getReferralChartData`).
- Удалить загрузку `adminMarketingService.listPromoCodes()`.
- Заменить заголовок `AdminTabbedHeader` на "Партнерская программа".
- Развернуть содержимое `referralsContent` из старых вкладок в прямой рендеринг страницы.

### 3.3. Страница Промокодов (`/admin/promocodes/page.tsx`)
- Создать новую страницу.
- Загружать только `adminMarketingService.listPromoCodes()`.
- Использовать `AdminTabbedHeader` с заголовком "Промокоды".
- Отрендерить таблицу `PromoCodeTable` и модалку `CreatePromoModal`.

### 3.4. Удаление лишнего кода
- Удалить `src/app/admin/marketing/client-tabs.tsx`.

## 4. Требования к безопасности и правам доступа (RBAC)
- Обе страницы должны использовать `enforceSectionAccess('marketing')` (поскольку концептуально обе относятся к правам маркетинга).
- На странице промокодов проверка `canEdit` должна определять видимость `CreatePromoModal` точно так же, как это было реализовано ранее.
- Разделение не должно повлиять на права доступа `staffRole`.

## 5. План тестирования (QA)
- E2E тесты (проверка роутов админки).
- Unit тесты (`admin-nav-active.test.ts`) должны корректно резолвить новый алиас `/admin/promocodes` к `/admin/finance`.
- Визуальная проверка: отсутствие двойных табов, отсутствие горизонтального скролла в `PromoCodeTable` (по правилу Zero Column Clipping).
