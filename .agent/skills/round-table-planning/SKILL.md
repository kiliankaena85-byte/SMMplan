# Круглый стол планирования (Smmplan Edition) 👥

Этот скилл организует проработку сложных технических задач силами **синтетического круглого стола узких специалистов**. Каждый аспект плана критикуется и дополняется отдельной ролью, что предотвращает слепые зоны и выявляет скрытые риски до написания кода.

## When to activate

Скилл активируется в следующих случаях (согласно Фазе 1: Triage):

| Триггер активации | Условие и критерии для запуска |
|---|---|
| Явный запрос пользователя | Запросы со словами "спланируй", "круглый стол", "оцени риски", "round table", "threat model". |
| Высокая сложность задачи | Изменения затрагивают более 2 смежных систем (например, Frontend + DB + API). |
| Опасность регрессии | Изменения в платежных шлюзах (YooKassa, CryptoBot), авторизации, или миграциях БД. |
| Архитектурные изменения | Переработка структуры БД, ORM Prisma, или крупные визуальные рефакторинги (например, корзина). |

## Step-by-step execution protocol

Выполнение скилла строго делится на две фазы и шесть последовательных шагов.

### Шаг 0: Триггер и активация
Агент распознает сложную задачу и запускает Фазу 1 (Triage) согласно `references/triage.md`.

### Шаг 1: Triage и Открытие модератора
Модератор проводит быстрый анализ сложности задачи:
1. Выбирает уровень глубины (Level 0 - Skip, Level 1 - Lite, Level 2 - Standard, Level 3 - Deep).
2. Формирует динамический состав участников круглого стола (от 3 до 7 ролей).
3. Объявляет запуск раунда планирования.

### Шаг 2: Технический раунд (Техника)
Специалисты проводят технический аудит архитектуры:
1. **Архитектор** задает общую структуру решения и API контракты на базе Next.js 16 и React 19.
2. **Data Engineer** проектирует изменения схемы в `schema.prisma` и планирует миграции.
3. **Security (STRIDE)** анализирует угрозы, доступность прав (`requireAdmin`) и защиту данных.
4. **Performance** оценивает N+1 запросы в БД и задержки бэкенда.
5. **Frontend Performance** контролирует объем бандла и рендеринг HeroUI v3.

> [!NOTE]
> В процессе технического аудита специалисты **обязаны** обращаться к векторной памяти проекта (RAG), выполняя команду:
> ```bash
> npx tsx scripts/query-rag.ts "<вопрос по архитектуре или логике>"
> ```
> Это позволяет использовать контекст существующих KIs и избегать дублирования логики.

### Шаг 3: Продуктовый раунд (Продукт)
Участники оценивают план со стороны пользователя:
1. **UI/UX Дизайнер** строит сценарии переходов (User Flow) в Mermaid и проверяет a11y.
2. **Product Manager** определяет приоритеты фич, ключевые бизнес-метрики и фазы раскатки.

### Шаг 4: Раунд QA-инженера (Качество)
Тестировщик формирует стратегию верификации:
1. Описывает критерии готовности (DoD) для каждого шага.
2. Задает пограничные сценарии (Edge-cases).
3. Описывает сценарии отката изменений (Rollback) в случае сбоя деплоя.

### Шаг 5: Синтез модератора и создание контракта
Модератор разрешает конфликты между специалистами, строит таблицу компромиссов (Trade-offs) и формирует два вывода:
1. Чат-выжимка (рецепт) для разработчика по стандарту `references/developer-output.md`.
2. Полный файл плана в директории `.planning/` согласно шаблону `references/plan-template-compact.md` или `references/plan-template.md`.

## Scope boundaries

Скилл строго очерчивает свои границы для сохранения эффективности.

### In scope
- Анализ архитектуры, БД, безопасности и UX перед написанием кода.
- Поиск конфликтов интересов (например, безопасность против производительности).
- Симуляция рисков деплоя и отката для Next.js 16 и Prisma 5.
- Автоматическая проверка контекста через `scripts/query-rag.ts`.

### Out of scope
- Написание и имплементация исходного кода (код пишется после согласования плана).
- Запуск тестов сборки или линтинга (выполняется утилитами preflight).
- Замена реального пользовательского тестирования (количественного/качественного).

## Error handling

В случае возникновения непредвиденных сбоев во время прогона:

| Ошибка | Сценарий восстановления |
|---|---|
| Сбой выполнения RAG-скрипта | Если `scripts/query-rag.ts` возвращает ошибку, продолжить ручной анализ на основе открытых файлов и KI-базы, уведомив пользователя о сбое индексатора. |
| Конфликт интересов ролей | Если технические требования противоречат продуктовым, модератор фиксирует конфликт в таблице Trade-offs для финального решения пользователем. |
| Запрос обхода планирования | Если пользователь требует "сделать быстро без плана", вывести краткое предупреждение о рисках и переключиться в Level 0. |
