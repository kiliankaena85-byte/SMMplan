## 1. Назначение и бизнес-цели

Разработка высоконадежной, юридически защищенной и прозрачной для человека системы автономного ИИ-ассистента клиентской поддержки в SMM-панели OmniSMM 1.0.

### Ключевые требования заказчика:
1. **Таргетированное подключение (Rollout Engine):**
   - Глобальное отключение (Kill-Switch: `DISABLED`);
   - Режим тестирования на тестировщиках (`WHITELIST_ONLY`: только указанные email/ID);
   - Канареечный запуск (`CANARY`: X% пользователей);
   - Полный запуск (`ALL_USERS`).
2. **Система исчерпания квот и отказов (Fail-Safe Circuit Breaker):**
   - При исчерпании квот Gemini (HTTP 429) или сбое шлюза 100% обращений прозрачно и без ошибок переводятся на дежурных операторов.
3. **100% прозрачность и Human-in-the-Loop:**
   - Все сообщения ИИ видны операторам в реальном времени с бейджем `🤖 ИИ-Ассистент`.
   - Оператор имеет кнопку моментального перехвата диалога (`[🛑 Перехватить диалог]`), навсегда отключающую ИИ в этом тикете.
4. **Защита от BOLA / IDOR и брутфорса:**
   - Авторизованный поиск заказов привязан строго к `session.userId`.
   - Для гостей: запрет раскрытия ссылок на каналы, лимит попыток (Rate Limit), одноразовый OTP-код на почту при запросе статуса.
5. **Юридический комплаенс (РФ 2026):**
   - 152-ФЗ (деперсонализация ПДн ДО отправки в облачные LLM);
   - ЗоЗПП ст. 26.1 / 115-ФЗ (возвраты строго на исходное платежное средство);
   - 38-ФЗ ст. 15 (запрет недостоверных гарантий «100%»);
   - Запрет признания вины («это наша вина», «мы нарушили закон»);
   - Обязательный AI-дисклеймер в каждом сообщении.

## 2. Архитектура компонентов (Clean Architecture)

```

│                              OmniSMM 1.0 AI Support Architecture Layers                               │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Layer 0: Domain & Types                                                                                │

├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Layer 1: Data Sanitization & Security (152-ФЗ & Anti-IDOR)                                             │
│ • `PiiScrubberService`: зачистка email, телефонов, карт, JWT-токенов перед обращением к LLM           │

│ Layer 2: Deterministic Decision Gateway (CPU / ONNX)                                                   │
│ • `DecisionGatewayService`: Tier 0 Fast Regex (<0.5 мс) + Tier 1 Laya Client (:8009, 15 мс) + Fallback │
│ • Docker microservice `docker/laya`: Laya 421M ONNX int8 на CPU (choice, score, noul)                  │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Layer 3: Cognitive & Grounding Core                                                                    │
│ • `ContextBuilderService`: сборка среза заказов, баланса и RAG-знаний GraphRAG (:8100)                │
│ • `GeminiSupportClient`: вызов Gemini Flash через Multi-Proxy pool (`UniversalNetworkRouter`)         │
│ • `GroundingGuardService`: сверка чисел, сумм и статусов ответа с реальной базой данных                │

├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Layer 4: Orchestration, Resilience & Quotas                                                            │
│ • `AiAgentOrchestratorService`: управление циклом диалога, Circuit Breaker на 429, эскалация          │
│ • `takeoverTicketAction`: серверный экшн оператора для мгновенного отключения ИИ в тикете              │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Layer 5: UI/UX & Operator Cockpit                                                                      │
│ • Поддержка `sender: 'AI_AGENT'` в `TicketChat` с бейджем и кнопкой перехвата                          │
│ • Отображение скрытых диагностических брифов `INTERNAL` для операторов                                │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

## 3. Матрица отказов и премортем (Failure Simulation)

| Сценарий отказа | Вероятность x Влияние | Защитный механизм в коде | Что получает клиент |
|---|---|---|---|
| **Исчерпание квоты Gemini (HTTP 429)** | Высокая x Критическое | `AiAgentOrchestrator` ловит 429, ставит `circuit:ai:quota_exhausted` в Redis на 15 мин, отправляет алерт в Telegram и переводит тикет оператору. | Вежливое уведомление о постановке в очередь операторов без ошибок. |
| **Падение контейнера Laya (:8009)** | Средняя x Среднее | Таймаут 50 мс (`AbortSignal.timeout`). При ошибке управление передается Tier 0 Regex-эвристикам. | Штатный ответ без задержки. |
| **Попытка перебора заказов (Brute-Force)** | Высокая x Критическое | Redis Rate-Limit (макс 3 попытки/15 мин на IP) + требование ввода OTP из email для неавторизованных. | Требование подтверждения владения через email, бан IP при спаме. |
| **Попытка IDOR (чужой номер заказа)** | Высокая x Критическое | `OrderLookupTool` принудительно фильтрует `where: { id, userId: session.userId }`. | «Заказ не найден в Вашем личном кабинете». |
| **Выдуманная сумма / обещание возврата** | Средняя x Высокое | `GroundingGuard` и `OutputPolicyEngine` сканируют ответ. При нарушении ответ блокируется, тикет идет человеку. | «Вопрос передан старшему менеджеру». |
| **Конфликт: Оператор пишет одновременно с ИИ** | Высокая x Среднее | Любое ручное сообщение оператора атомарно переводит `aiHandlingState = 'SUSPENDED_BY_STAFF'`. | ИИ мгновенно замолкает, оператор контролирует диалог. |

## 4. Спецификация тестового покрытия (TDD Test Suite)

1. `pii-scrubber.test.ts`: 100% очистка email, карт, телефонов, токенов, сохранение контекста.
2. `order-lookup-security.test.ts`: Защита от IDOR, запрет выдачи ссылок на каналы, гостевая блокировка.
3. `decision-gateway.test.ts`: Tier 0 стоп-слова, эскалация при ярости, отказоустойчивость при падении Laya.
4. `output-dlp.test.ts`: Блокировка утечек ссылок на каналы, промптов и API-ключей.
5. `rollout-and-circuit-breaker.test.ts`: Тестирование `WHITELIST_ONLY`, `CANARY`, `DISABLED`, реакция на HTTP 429.
6. `operator-takeover.test.ts`: Атомарный перехват тикета оператором и отключение ИИ.
