## Подробный трейсинг UI-потоков

### Поток 1: Импорт услуг от провайдера
**Цепочка шагов**: `/admin/providers/new` → `testConnection` → `/admin/providers/import` (Cherry-Pick Wizard) → `создание Service`

1. **Создание провайдера (`/admin/providers/new`)**:
   - Поля формы: `name`, `apiUrl`, `apiKey`, `balanceCurrency`, `ticketUrl`, `mapping` (Visual / JSON режимы).
   - Валидация: Zod на сервере + JIT-проверка заполнености полей на клиенте.
   - `testConnection`: Функция `handleCheck()` вызывает `checkProviderConnection()`, проверяет баланс и статус API, выводит результаты через Toast notifications.
   - **После создания**: Сервер возвращает `{ success: true }`, выполняется `router.push('/admin/providers')` с автоматическим редиректом.

2. **Cherry-Pick Import Wizard (`/admin/providers/import`)**:
   - Интерактивный мастер импорта состоящий из 3 фаз (Выбор провайдера → Поиск/Фильтрация/Кастомная наценка → Итоговое подтверждение `ConfirmationModal`).
   - Имеется AI-автомаппинг категории по ключевым словам и платформе (`autoMapCategory`).
   - При Submit отправляется `importSelectedServices()`, сервер возвращает созданные ID и пропускает дубликаты.
   - Выводится итоговый отчёт через Toast ("Успешно импортировано N услуг").

3. **Результат импорта**:
   - Услуги сохраняются в СУБД с привязкой к выбранной категории и сети.
   - Мгновенно отображаются в таблице каталога `/admin/catalog`.

**Статус Потока 1**: ✅ **РАБОТАЕТ**

### Поток 2: Настройка маппинга API
**Цепочка шагов**: `/admin/providers/[id]` → Изменение полей → Сохранение

1. **Маппируемые поля**: `httpMethod`, `contentType`, `authType`, `authField`, `authPrefix`, `serviceField`, `linkField`, `quantityField`, `orderIdField`, `errorField`, `itemsPath`, `serviceIdField`, `nameField`, `priceField`, `minField`, `maxField`, `typeField`, `descField`, `balancePath`, `currencyPath`.
2. **Сохранение**: Вызов `updateProvider(id, payload)` обновляет JSON-структуру `mapping` в таблице `Provider`.
3. **Использование при sync**: Метод `syncProviderCatalog()` читает структурированный `mapping` или использует нормализаторы `UniversalProvider` по умолчанию.
4. **Визуализация**: Поддерживается два режима — удобный конструктор Visual Builder и сырой JSON Editor с двусторонней валидацией синтаксиса.

**Статус Потока 2**: ✅ **РАБОТАЕТ**

### Поток 3: Публикация и добавление на витрину
**Цепочка шагов**: Ручное переключение в `/admin/catalog` → Витрина `/services`

1. **Флаги видимости**:
   - `isActive` — включение/отключение конкретной услуги.
   - `isQuarantined` — изоляция при подозрительных изменениях цен.
   - `cooldownUntil` — временно замороженные услуги.
2. **Управление флагами**: Интерактивные переключатели `Switch` в `CatalogTable` мгновенно вызывают Server Action `toggleServiceActiveAction()`.
3. **Quality Gate (≥3 услуг)**:
   - В клиентской витрине (`/services/[network]/[category]/page.tsx`) проверяется `services.length >= 3`.
   - Если условие не выполнено, генерируется метатег `robots: { index: false, follow: false }`.
   - В `sitemap.ts` категории с <3 услугами автоматически исключаются из генерации sitemap.xml.
4. **Отображение цен**: В UI отображается конечная цена за 1 штуку в рублях (`pricePerUnitRub`), рассчитываемая от `pricePer1000Cents` и текущего курса USD/RUB.

**Статус Потока 3**: ✅ **РАБОТАЕТ**

### Поток 4: Редактирование параметров услуги
**Цепочка шагов**: Клик по строке таблицы `/admin/catalog` → Открытие слайдера/модалки → Сохранение

1. **Доступные поля**: Название (`name`), описание (`description`), наценка (`markup`), `minQty`, `maxQty`, привязка к сети/категории.
2. **Защита от фоновой синхронизации (Sync Protection)**:
   - При изменении названия или описания вручную устанавливаются флаги `isCustomName = true` и `isCustomDescription = true`.
   - Фоновая синхронизация `syncProviderCatalog` не перезаписывает данные поля у провайдера.
3. **Кнопка сброса**: Action `resetCustomFlagsAction` сбрасывает флаги и возвращает имя/описание от провайдера.
4. **Динамический пересчет**: Изменение наценки мгновенно пересчитывает розничную цену с учетом коэффициента `applyBeautifulRounding`.

**Статус Потока 4**: ✅ **РАБОТАЕТ**

### Поток 5: Мульти-роутинг провайдеров
**Цепочка шагов**: `/admin/services/[id]/routing` → `RoutingPanelClient`

1. **Настройка резервных провайдеров**:
   - Можно привязать несколько провайдеров к одной услуге в таблице `ServiceRoute`.
   - Указываются приоритеты (`priority: 0, 1, 2...`), где `0` — основной (Primary).
2. **Автоматический Hot-Swap**:
   - При сбое основного провайдера система автоматически переключает вызов на следующий резервный маршрут.
3. **UI Управления**:
   - Реализована интерактивная панель `RoutingPanelClient` и хук сравнения SLA/цен `ProviderComparisonHub`.
   - Сохранение выполняется мгновенно через Server Actions (`addServiceRoute`, `changeRoutePriority`, `executeHotSwap`).

**Статус Потока 5**: ✅ **РАБОТАЕТ**

### Поток 6: Сопутствующее управление и мониторинг

1. **Batch-операции (`/admin/catalog`)**:
   - Работают пакетные операции: `batchUpdateMarkup`, `batchToggleStatus`. Массив ID ограничен лимитом в 200 записей.
2. **Карантин (`/admin/catalog/quarantine`)**:
   - Таблица разделена на три вкладки: `Price Spikes` (скачки цен), `Zombies` (удаленные провайдером), `API Errors` (сбои подключения).
   - Доступны кнопки одобить/отклонить (`approveQuarantinedService`, `rejectQuarantinedService`).
3. **Мониторинг дрифта цен (`/admin/catalog/drift`)**:
   - Показывает плавные изменения цен провайдеров от 5% до 20% за 30 дней.
4. **AI-Обогащение (`/admin/catalog/enrichment`)**:
   - Клиентская таблица `EnrichmentClientTable` с кнопкой вызова AI для сбора описаний с сайта провайдера.
