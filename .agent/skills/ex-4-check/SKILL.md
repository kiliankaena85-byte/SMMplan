# 🔷 EX-4: CHECK — Самопроверка

## МОЯ ЕДИНСТВЕННАЯ ЗАДАЧА
Найти все technical проблемы в коде ДО передачи Reviewer'у.
Я не пишу новый код. Я не передаю Reviewer'у бизнес-оценку.
Я только проверяю технику — жёстко и системно.

---

## ШАГ 1: ПРИНИМАЮ ВСЕ BATON

Из BATON-1: стадия → строгость проверки
Из BATON-2: план → всё ли реализовано по плану?
Из BATON-3: компромиссы → осознанные ли они?

---

## ШАГ 2: ЧЕКЛИСТ КОРРЕКТНОСТИ

□ Все требования из BATON-2 выполнены?
□ Все шаги плана реализованы?
□ Все checkpoint'ы из плана пройдены?
□ Все edge-cases из плана обработаны?
□ Работает с null/undefined/пустыми значениями?
□ Нет off-by-one ошибок?
□ Нет race condition (если асинхронный код)?

---

## ШАГ 3: ЧЕКЛИСТ КАЧЕСТВА

□ Нет дублирования кода (DRY)?
□ Каждая функция делает одно (SRP)?
□ Имена говорящие и консистентные?
□ Нет функций длиннее 40 строк?
□ Нет вложенности глубже 3 уровней?
□ Структура файлов соответствует стандарту?
□ Стиль единообразен с остальным проектом?
□ Нет debug-кода?
□ Нет TODO без тикета?

---

## ШАГ 4: ЧЕКЛИСТ БЕЗОПАСНОСТИ

□ Пользовательский ввод валидируется на границах?
□ SQL: параметризованные запросы (не конкатенация)?
□ Секреты не хардкодятся?
□ Нет утечки чувствительных данных в логах?
□ Аутентификация/авторизация проверяется?
□ Нет path traversal уязвимостей?

Если найдена уязвимость → помечаю 🔴 SECURITY ISSUE

---

## ШАГ 5: ЧЕКЛИСТ ПРОИЗВОДИТЕЛЬНОСТИ
(обязателен для Scale, рекомендован для Growth)

□ Нет N+1 запросов к БД?
□ Большие списки пагинируются?
□ Нет утечек памяти (незакрытые соединения, подписки)?
□ Алгоритмическая сложность адекватна объёму данных?
□ Нет синхронных операций там где нужен async?

---

## ШАГ 6: ИТОГОВЫЙ ВЕРДИКТ ПРОВЕРКИ

ЕСЛИ найдены критичные проблемы:
→ Возвращаю в ex-3-build с описанием проблем
→ НЕ передаю дальше пока не исправлено

ЕСЛИ всё OK или только минорные замечания:
→ Формирую BATON-4 и передаю в ex-5-handoff

---
